# Промпт: Privacy Gateway (Windows, fail-closed)

Напиши нативное десктопное приложение «Privacy Gateway» — контроль исходящего
сетевого трафика по принципу fail-closed: выбранные пользователем программы
ходят в сеть ИСКЛЮЧИТЕЛЬНО через его прокси-туннель, а если туннель упал —
не ходят вообще. Никакого fallback на прямое соединение, никаких bypass-правил.
Трафик НЕ выбранных приложений не трогается вообще.

Формат проекта — как в Arbogeo: Rust-ядро в воркспейс-крейтах, привилегированная
Windows-служба над ним, десктоп-оболочка на Tauri 2.x, фронтенд — pnpm-workspace
(Vite + React + TS + Tailwind + React Aria) на собственных токенах дизайна.

Протоколы и перехват трафика мы не реализуем сами: этим занимается **sing-box**,
как в NekoBox. Ядро разбирает share-links, собирает конфиг sing-box и следит за
процессом; per-process перехват — TUN-вход плюс правила маршрутизации по
`process_path`, без своего драйвера.

## Платформа

Windows 10/11 (x64 и arm64). Один установщик (NSIS/MSI), без сторонних
рантаймов. WebView2 Runtime — единственная системная зависимость GUI.

## Протоколы туннелей

VLESS, VMESS, Trojan, Shadowsocks, Hysteria2, WireGuard. Ввод — share-links
(`vmess://`, `vless://`, `trojan://`, `ss://`, `hy2://`, `wg://`) и/или JSON.

## Структура

```
crates/                Rust-крейты (воркспейс)
  core-config/         парсер share-links и JSON-конфигов → узел sing-box
  core-tunnel/         генерация конфига sing-box, запуск и присмотр за
                       процессом, проба здоровья через SOCKS5, счётчики трафика
  core-filter/         политика fail-closed + блокирующие правила брандмауэра
                       на выбранные .exe (страховка на время без sing-box)
  core-apps/           автообнаружение приложений по стандартным путям,
                       разрешение путь ↔ PID, охват дочерних процессов
  core-ipc/            контракт службы ↔ клиент (типы запросов/событий, serde)
  pg-service/          Windows Service: владеет процессом sing-box и правилами
                       брандмауэра, слушает 127.0.0.1 (построчный JSON)
  pg-cli/              headless-клиент поверх core-ipc (один бинарник)
src-tauri/             Tauri 2.x десктоп-обёртка; грузит сборку app-shell в
                       нативное окно, запускается от обычного пользователя,
                       управляет службой через core-ipc
ui/                    pnpm-workspace (фронтенд)
  app-shell/           Vite+React+TS+Tailwind+React Aria — оболочка
    src/platform/      рантайм-детект `isTauri()` + вызовы службы
  modules/
    apps/              список приложений, добавление .exe, галочки
    profiles/          импорт share-link/JSON, профили, редактирование
    status/            статус туннеля, задержка, трафик, активные процессы
    logs/              журнал понятным языком
  packages/
    design-tokens/     токены (CSS-переменные + TS-объект)
    ui-kit/            примитивы на токенах (Button, Toggle, Badge)
resources/apps/        каталог известных приложений (catalog.v1.json)
installer/             WiX/NSIS, подпись драйверов, автообновление
```

## Границы модулей

- **core ничего не знает про GUI.** Единственный интерфейс — `core-ipc`.
  И Tauri-оболочка, и CLI — тонкие клиенты одного и того же контракта.
- **Привилегии живут только в службе.** GUI и CLI работают от обычного
  пользователя; всё, что трогает WFP/TUN, — внутри `pg-service`.
- **Состояние — у службы.** GUI подписан на события (статус, трафик, падение
  туннеля), не опрашивает и не хранит копию истины.

## Fail-closed механика

1. Туннель не поднят → политика DROP для выбранных процессов.
2. Туннель поднят → выбранные процессы идут только в него. Запасного маршрута у
   них в конфиге нет, поэтому недоступный сервер сам по себе означает отказ.
3. Падение процесса sing-box обнаруживается присмотром службы → блокирующие
   правила брандмауэра до подтверждённой пробы туннеля.
4. Дочерние процессы выбранного exe попадают под те же правила.
5. Служба убита сигналом → осиротевший sing-box добивается при следующем старте
   по pid-файлу, чтобы TUN не жил без присмотра.

## GUI

Экран списка приложений (автообнаружение + ручное добавление по пути к .exe),
переключатель «Приватный режим», импорт конфигов и профили, статус туннеля,
логи. Русский и английский. Никакого веб-фронтенда снаружи: только локальная
сборка в Tauri-окне.

## CLI

`privacy-gateway on --profile myvpn`, `off`, `status`, `list-apps`, `discover`,
`add-app --path`, `enable --path`, `disable --path`, `add-profile --link`,
`profiles`.

## Разработка

```bash
pnpm install
pnpm --filter app-shell dev      # дев-сервер фронтенда
pnpm validate                    # единый гейт: lint + build + cargo test
cargo tauri build                # десктоп-сборка (только Windows)
PG_SINGBOX=... scripts/e2e.sh    # сквозная проверка на своём же сервере
```

## Тесты

- Парсер share-links: таблица «строка → конфиг», включая мусор и краевые случаи.
- Fail-closed: политика в каждом состоянии + сквозной прогон `scripts/e2e.sh`
  (свой vless-сервер, трафик через туннель, убийство сервера → отказ).
- Сгенерированные конфиги проверяются настоящим `sing-box check`.
- `core-apps`: раскрытие `%VAR%` в путях каталога и отсев несуществующих.

## Принципы

- **Офлайн:** обязательных сетевых вызовов нет, кроме самого туннеля и
  (опционально) проверки обновлений. Никакой телеметрии, никаких логов трафика,
  ничего наружу.
- **Ничего скрытого:** всё, что делает программа, видно в интерфейсе.
- **TS strict** во всех пакетах; Rust — `#![deny(warnings)]` в CI.

## Что НЕ делать

- Не проксировать всю систему — только выбранные приложения.
- Не добавлять исключения и bypass для выбранных приложений.
