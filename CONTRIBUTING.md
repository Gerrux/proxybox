# Как помочь proxybox

*English: this file is Russian, like the rest of the docs — Russian is the
project's source language. Issues and pull requests in English are welcome all
the same; someone will answer. Build instructions are in
[docs/development.md](docs/development.md), and the README exists in six
languages.*

Помощь нужна разная, и код — не самая дефицитная её часть.

## Что нужно больше всего

**Проверка на живой Windows.** Проект собирается и тестируется на Linux, а
работает только на Windows: TUN, брандмауэр, служба SCM, установщик. Целый
список того, что не проверял никто, лежит в
[docs/limitations.md](docs/limitations.md) — «на живой Windows проверено не
всё», миграции переименования, шестиязычный установщик. Отчёт «поставил, вот что
вышло» стоит дороже патча.

**Переводы.** Языков шесть, и ни один, кроме английского, не читал носитель.
Тесты стерегут, что строка переведена, а не что переведена верно. Таблицы лежат
в `crates/core-ipc/src/dict.rs` (служба и CLI) и
`ui/app-shell/src/i18n.ts` (окно); экраны помощи CLI — константы `USAGE_*` в
`crates/pg-cli`. Раскладку справа налево (фарси) живьём тоже никто не смотрел.

**Отчёты об ошибках.** К каждому приложите вывод `proxybox doctor` — он
проверяет не наш код, а окружение, и половина отказов объясняется им же.

## Прежде чем писать код

Заведите issue, если правка больше однострочной. Проект держится на нескольких
жёстких инвариантах, и правка, спорящая с ними, отклоняется не из вредности —
разбор в [docs/how-it-works.md](docs/how-it-works.md) и в `CLAUDE.md`. Главный
из них один:

> Приватный режим включён + туннель не подтверждён = выбранные приложения без
> сети. Промежуточных состояний с прямым доступом не существует, bypass-правил
> нет.

Из него следует то, что чаще всего предлагают и что не принимается: правило
«пустить это приложение мимо туннеля», маршрут `direct` в конфиге, снятие
запрета вместо выдачи пропуска.

## Сторожа

Правило со словом «обязан» заводится вместе с тестом, и абзац документации
ссылается на тест по имени. Без сторожа правило не соблюдается — проверено.
Поэтому:

- новая инвариантная связь между двумя местами — это новый `#[test]` с говорящим
  именем (`the_pass_is_bound_to_the_tunnel_address`, `nothing_can_go_direct`);
- упавший сторож — это либо ваша ошибка, либо устаревшее правило, и второе
  чинится правкой документации вместе с тестом, а не удалением теста.

Тестов-файлов в проекте нет, всё в `#[cfg(test)] mod tests` внутри модуля.

## Сборка и проверка

Всё в [docs/development.md](docs/development.md); минимум перед PR:

```bash
pnpm install
pnpm validate     # tsc --noEmit + vite build + cargo test --workspace
```

`pnpm validate` — то же, что бежит в CI. Отдельной строкой, только в CI и только
под Windows-целью, проверяется оболочка: `src-tauri` вынесена из воркспейса, и
`cargo test --workspace` её не трогает вовсе.

```bash
cargo check --workspace --target x86_64-pc-windows-msvc   # windows-ветки
```

## Пулл-реквесты

- Одна тема на PR. Причёсывание соседнего кода заводите отдельно — так его можно
  принять, не задерживая основную правку.
- Сообщение коммита — по-русски, одной строкой, и говорит про **последствие**, а
  не про действие: не «добавил проверку в fetch», а «подписка качалась по http,
  и адрес мог сохраниться раньше проверки». Так написана вся история; загляните
  в `git log`.
- Комментарии объясняют «почему», а не «что». Шапка модуля — рационал целиком.
- Сознательное упрощение с известным потолком помечается комментарием
  `ponytail:` с указанием потолка и пути апгрейда.
- Закрыли пункт из `docs/limitations.md` — уберите его оттуда в том же PR.

## Чего в проект не приносят

Телеметрию, аналитику, логи трафика и «анонимную статистику» в любом виде.
Наружу продукт ходит по трём адресам: сервер самого пользователя, `ip-api.com`
за точкой выхода (через туннель, выключается настройкой) и `api.github.com` за
обновлениями по нажатию кнопки. Четвёртого не будет.

Зависимости — по необходимости, а не по удобству: служба ходит от LocalSystem, и
каждый крейт в ней это чужой код с полными правами на машине. Клиенты
(`src-tauri`, `pg-cli`) держит храповик `the_clients_stay_thin` — `core-config`
или `core-filter` у клиента роняет тест.
