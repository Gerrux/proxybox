# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Язык репозитория — русский: комментарии, доки, сообщения коммитов, строки
журнала и интерфейс. Пишите так же.

## Команды

```bash
pnpm install
cargo run -p pg-service                    # служба (терминал 1); на Linux нужен root (TUN, nftables) — без него PG_SOCKET на свой путь
cargo run -p pg-cli -- doctor              # почему не работает: окружение, не код
pnpm --filter app-shell dev                # фронтенд на :5173, ходит в службу сам
cargo tauri dev                            # окно (только Windows)

pnpm validate                              # tsc --noEmit + vite build + cargo test --workspace
                                           # то же бежит в CI на каждый PR (ci.yml)
cargo test -p core-config vless            # один тест / один крейт
cargo check --workspace --target x86_64-pc-windows-msvc   # windows-ветки без линковки
PG_SINGBOX=/путь/к/sing-box scripts/e2e.sh # сквозная проверка fail-closed
scripts/settings.sh                        # настройки: правка, диск, окружение
python3 scripts/worldmap.py                # карта мира окна (worldmap.ts) из Natural Earth
```

`src-tauri` — отдельный Cargo-проект (`exclude` в воркспейсе): `cargo
test/check --workspace` его не трогает. Компилятор до неё всё-таки дотягивается,
но отдельной строкой и только в CI: `cargo check --manifest-path
src-tauri/Cargo.toml --target x86_64-pc-windows-msvc`. Локально то же самое
требует `llvm-rc` (его зовёт build.rs) и пустышек в `src-tauri/binaries/` —
линковки при `check` нет, а существование вложенных бинарников build.rs
проверяет. Пока этой строки не было, новый вариант `Scope` не сломал ни одного
теста и всплыл только `cargo tauri build` на живой Windows.
Тестов-файлов нет, всё в `#[cfg(test)] mod tests` внутри модуля.

Переменные: `PG_SINGBOX` (путь к бинарнику), `PG_TUN=0` (не поднимать TUN),
`PG_PROBE=host:port` (цель пробы), `PG_REFRESH=0` (не сверять подписки сами),
`PG_STACK=system|gvisor|mixed` (чем разбирать пакеты из TUN, по умолчанию
`mixed`), `PG_PPROF=127.0.0.1:48294` (профилировщик sing-box; пусто — выключен),
`PG_SOCKET=/путь/к/сокету` (где вне Windows слушает служба, по умолчанию
`/run/proxybox/service.sock`; каталог для умолчания создать может только
root, и без переменной служба без root не поднимается вовсе).
Последние четыре, как и `PG_TUN`, настройкой не продублированы: все
диагностические, человеку выбирать там нечего, а включённый по недосмотру
профилировщик — это открытый порт в службе, которая ходит от LocalSystem.
Значение стека уходит в конфиг без
проверки — `sing-box check` имя стека не смотрит, а подстановка умолчания
вместо непонятого значения давала бы замер, который врёт. Остальные
продублированы настройками (`Settings` в контракте) и переменной перебиваются:
окружение сильнее, но на диск не пишется. Состояние — `%ProgramData%\proxybox\`;
под root на Linux — `/var/lib/proxybox` (у root `$XDG_CONFIG_HOME` указывала бы
в `/root/.config`), без прав — `$XDG_CONFIG_HOME` или домашний `~/.config`:
`state.json`, `singbox.json`, `singbox.log`.

Каталог состояния служба запирает сама, и порядок тут обязателен. `secure_dir`
идёт **до** `Service::load()`: права файла копируются от каталога в момент
создания, а первую же строку журнала служба кладёт на диск сама — заперев
каталог позже, `state.json` с паролями профилей так и остался бы читаемым всей
машиной. `secure_tree` (обход `/T` по тому, что лежало в каталоге до нас) —
наоборот, **после** восстановления приватного режима: до `guard` выбранные
приложения ходят напрямую, и расширять это окно обходом диска, на котором лежат
профили браузера, нельзя. Владелец переставляется, а не проверяется: у чужого
владельца всегда есть право переписать DACL обратно. Делает это `icacls` с
SID-ами вместо имён групп — своя обёртка над дескрипторами дала бы то же самое
ценой unsafe-FFI и собственного обхода каталога, а имена групп на
локализованной Windows не встают. Сторож —
`the_state_directory_is_locked_to_system_and_admins`.

На Linux этого нет: правами `0o700` на сам каталог закрыто и всё, что внутри,
обходить содержимое незачем, и `secure_tree` там сразу выходит — вопрос уже
решён правами каталога, а не деревом (`secure_dir`/`secure_tree` в
`crates/pg-service/src/main.rs`).

## Инвариант

Приватный режим включён + туннель не подтверждён = выбранные приложения без
сети. Промежуточных состояний с прямым доступом не существует, bypass-правил
нет — кроме исключений (`Status::bypass`), которые заводит сам человек, и
только тогда, и правил охвата «раздельно» (ниже). Всё остальное в архитектуре —
следствие.

Исключения — адреса, сети и имена, до которых выходной узел не дотягивается
(облака и сервисы, закрытые от чужих стран). Они решают «куда», а не «кто»:
сети они не выдают никому, стена работает как прежде, и в белом списке
невыбранное приложение до TUN не доходит. Живут они в конфиге sing-box —
outbound с тегом `bypass` (не `direct`) и правила на него только с `tun-in`,
последними, `final` остаётся `proxy`; пустой список даёт конфиг до байта
прежний. Вход пробы под исключение не попадает никогда — иначе исключение на
подсеть хостера подтвердило бы мёртвый туннель (сторож —
`a_bypass_never_catches_the_probe`). Без TUN (прогон профилей, окна браузера)
исключений нет вовсе. Сверяет и приводит строки `core_tunnel::bypass_entry`:
шире `/8`, имя без точки (зона целиком), IPv6, пул FakeIP и подсеть TUN — отказ (сторож —
`a_bypass_entry_is_normalised_or_refused`). Соединение по исключению — не
утечка (`Conn::bypass`, сторож — `a_bypass_is_not_a_leak`). Сами исключения не
заводятся никогда: подсказки во вкладке соединений (`Conn::silent` — ноль
принятых байт за `SILENT_AFTER`, сторож `a_silent_conn_is_named`; и
`unreached` — адреса, молчащие и напрямую, по журналу sing-box, сторож
`a_dead_bypass_is_named`) только предлагают.

Охватов три (`Status::scope`): «белый список», «весь компьютер» и «раздельно».
Инвариант один и тот же, меняется только то, кого он касается.

«Раздельно» (`Scope::Split`) — весь трафик в туннель, кроме названного
человеком: выбранные приложения (`Settings::direct_apps`, правило по
`process_path`) и готовые наборы правил (`Settings::direct_rule_sets`, ссылки
`.srs`/`.json`) уходят мимо узла. Маршрут у них тот же, что у исключений, —
outbound `bypass`, и он один: тега `direct` по-прежнему нет, а `final` остаётся
`proxy`. Правила встают только на `tun-in`, после перехвата DNS, отбоя шлюза,
сниффинга и маршрута пробы, и только при TUN; входа `local` (проба, сеансы
браузера, прогон профилей) они не касаются. Сайты в этом охвате — не отдельный
список, а имена из исключений: поля `direct_domains` в `Settings` больше нет, а
прежнее содержимое `state.json` при загрузке переезжает в `Status::bypass`
(`Service::load`, сторож — `split_sites_move_into_the_exclusions`) и обратно не
пишется. Стена у охвата та же, что у «весь компьютер» (`fencing`): замок только
пока туннель не подтверждён, пропусков приложениям нет, `selected()` отвечает
пусто, так что приложение «напрямую» из белого списка никак не получает.
Соединение по любому из этих правил — `Conn::bypass`, а не утечка. Цена честная:
одно правило по `process_path` заставляет sing-box выяснять процесс **каждому**
соединению машины, до разбора правил и без сокращения ранним совпадением (замер
ниже), — порядок правил этого не меняет, и это плата за сам охват. Промах
матчера тих, но в безопасную сторону: приложение с несовпавшим путём идёт в
туннель, а не мимо него. Правила охвата
живут в конфиге, а не в стене, и потому вход в охват, выход из него и правка
приложений и наборов перезапускают туннель (`restart_routing`) — в отличие от
двух строгих охватов. Сторож конфига — `split_rules_share_the_bypass_outbound`.

Наборы правил в конфиг входят **локальными файлами** (`type: local`), а не
`remote`: удалённый набор sing-box качает сам на старте, и при недоступной
ссылке — то есть при мёртвом узле, ведь качает он через него — не запускается
вовсе, а проба, которой полагается сказать «узла нет», и автопереключение на её
промахах остаются без процесса (сторожа `a_dead_node_does_not_kill_singbox_in_split`,
`rule_sets_are_never_remote`). Файлы качает служба (`sync_rule_sets`) в
`rulesets/` каталога состояния — **только** сквозь подтверждённый туннель, без
прямого запасного пути (`rule_set_job`, сторож
`rule_sets_are_fetched_only_through_a_confirmed_tunnel`), только `https`
(`validate_direct`), с потолком размера и проверкой, что файл похож на набор
(`looks_like_rule_set`: страница ошибки с кодом 200 уронила бы sing-box на
старте). Набор без файла в конфиг не входит, и об этом строка в журнале
(`a_missing_rule_set_is_left_out_of_the_config`); докачка — на подтверждении
туннеля, при выборе набора и по сроку сверки подписок, а перезапуск один и
только когда файл у набора впервые появился. Файлы убранных наборов служба
стирает (`prune_rule_sets`). Безусловного `resolve` в конфиге нет: он тратил бы
поиск через `remote` на каждое соединение `tun-in`, а неудача поиска обрывала
бы соединение, которому адрес не нужен (сторож
`a_failed_lookup_never_drops_a_tunnel_bound_connection`). Цена названа: наборы
по IP (`geoip-ru`, `private`) срабатывают только на соединения, открытые прямо
по адресу, — имя остаётся FakeIP и идёт в туннель, пока его не назовёт доменный
набор или исключение; окно говорит об этом в выборе наборов.

Ещё один, `Scope::None`, — диагностический: тот же белый список, но `selected()`
отвечает пустым списком, поэтому пропусков не получает никто, а замок стоит.
`fencing` для него обязан совпадать с белым списком до знака — разойдись он, и
«в туннель не идёт никто» стало бы «идут все». Ставится только из CLI
(`proxybox scope none`) и в экране помощи не значится: он из той же семьи, что
`PG_STACK` и `PG_PPROF`. Окно знает его (иначе показывать состояние нечем), но
кнопки не даёт — сторожа `the_frontend_knows_the_same_scopes` и
`nobody_gets_a_pass_in_the_diagnostic_scope`.

Раньше был и другой split-tunnel («выбранные приложения»), где *невыбранные*
ходили напрямую. Он удалён целиком, и по двум причинам сразу. Он был единственной
дырой в приватности: правило по `process_path` сверяет путь побайтово, и промах у
него тихий — приложение уходило мимо туннеля, не переставая считаться
защищённым. И он же был самым дорогим режимом продукта: по замеру в
`docs/wfp.md` платится не за матчер по процессу, а за путь `direct` через TUN.
Вместе с ним из продукта исчез и `direct`. Нынешний «раздельно» устроен
наоборот: напрямую идёт только названное, по умолчанию всё в туннеле, а промах
матчера уводит приложение в туннель. Сохранённый старый охват читает
`migrate_scope` (сторож — `an_update_never_cuts_off_a_machine_that_was_not_asked`).

Белый список — это сеть только выбранным и только через туннель. Запрет всего
исходящего стоит в нашей стене (фильтры WFP, `core-filter`) всё время, пока
включён приватный режим, а выбранным при подтверждённом туннеле выдаётся
пропуск сквозь него — не запрет снимается, а пропуск выдаётся: снятие открыло
бы сеть всем. Разводит это одна функция `fencing()` в службе, сторож —
`the_whitelist_locks_the_door_and_hands_out_passes`.

Правда о судьбе приложения живёт в одном месте — `core_filter::policy()`;
`Tunnel::Down` в статусе означает именно DROP, а не «ошибку».

## Два слоя, и они не про отбор

Конфиг sing-box один на «белый список» и «весь компьютер», и это его главное
свойство: `final: proxy`, ни одного правила по `process_path`, тега `direct` в
`outbounds` нет вовсе (единственный маршрут мимо узла — тег `bypass`: исключения
и, только в «раздельно», правила охвата, и только когда человек их завёл) (у
WireGuard `outbounds` при этом пустой — 1.13.19 принимает и стартует, сторож —
`the_config_actually_starts`). Ни список приложений белого списка, ни охват в
конфиг не входят: `Options` не имеет под них полей, и сторож
`nothing_can_go_direct` сверяет набор полей — поле «охват» или «выбранные
приложения» не заведётся молча; в конфиг входят лишь собственные списки
«раздельно», исключения и каталог кэша наборов. У «раздельно» конфиг другой по
построению — `process_path` и наборы там есть, — но `direct` и там не
возвращается (`split_rules_share_the_bypass_outbound`).

Отсюда три следствия, каждое намеренное:

- «уйти напрямую» перестаёт быть тем, что мы запрещаем правилом: маршрута с
  таким тегом нет, а вместе с матчером по процессу исчезает и его тихий промах;
- переключение охвата и правка списка конфига не меняют, значит не
  перезапускают туннель — живые соединения (SSH) их переживают. Сторож —
  `editing_the_list_never_restarts_the_tunnel`;
- матчер по процессу в этих двух охватах не ставится ни разу (он есть только у
  «раздельно», по явному выбору человека), а он стоил дорого: одного такого
  правила где угодно в наборе хватало, чтобы sing-box выяснял процесс **каждому**
  соединению машины, до разбора правил и без сокращения ранним совпадением
  (проверено на 1.13.19). На Windows один такой поиск — снимок системной таблицы
  TCP/UDP плюс открытие чужого процесса; с ним же приходила жалоба на
  `MsMpEng.exe` рядом с sing-box.

Отбор живёт в стене и происходит на `connect`, до всякого TUN. Стена — это не
политика брандмауэра и не правила `netsh`, а пользовательский WFP: свои
постоянные провайдер и подслой и фильтры на `ALE_AUTH_CONNECT_V4/V6` и
`ALE_AUTH_RECV_ACCEPT_V4/V6` (`crates/core-filter`, `wall.rs` считает набор,
`wfp.rs` — единственный unsafe крейта — ставит его). Входящие закрыты тем же
замком, и это решение, а не следствие: на одном исходящем невыбранное
приложение с разрешающим правилом на вход (торрент, игровой сервер) принимало
бы соединение на физическом адаптере и обменивалось данными мимо туннеля.
Цена названа и принята: под замком нет входящего RDP/SSH на машину — в белом
списке всё время приватного режима, во «весь компьютер» пока туннель не
подтверждён, — и гости WSL2/Hyper-V,
идущие к службам хоста через vEthernet, тоже входящие. Сторож —
`the_lock_closes_the_door_inbound_too`. Деинсталляция снимает стену при
любом ответе диспетчера служб (`uninstall_always_takes_the_wall_down`): если
постоянный фильтр пережил службу, снимать его некому. Не встал полный набор —
транзакция откатилась, и на первой постановке это значило бы машину без
замка; поэтому следом ставится голый замок тем же построителем без пропусков
приложениям, а наружу всё равно уходит исходная ошибка, чтобы служба
повторила попытку (`a_failed_wall_falls_back_to_the_bare_lock`). Ключ
фильтра несёт версию схемы (`KEY_SCHEMA`, `the_key_carries_its_schema`):
сменится кодировка условия без смены описания — поднимите версию, иначе
постоянные фильтры прошлой сборки останутся стоять под тем же ключом. Держится она на том, что между подслоями побеждает
запрет: если наш подслой решил «блокировать», разрешения в подслоях Windows
Firewall его не отменяют. Внутри подслоя запрет весит 0, пропуска — 15
(`BLOCK_WEIGHT`, `PERMIT_WEIGHT`): названное пропуском проходит, всё остальное
ловит запрет. Политику машины (`blockoutbound` и прочее) мы не трогаем вовсе.

Раньше замком была как раз политика по умолчанию плюс разрешающие правила
`netsh`, и она не держала. Замер на машине разработчика: 232 включённых
исходящих разрешающих правила, среди них MSIX-приложения (Teams, Spotify,
Claude), — они открывали замок политики насквозь, и при мёртвом sing-box эти
приложения уходили напрямую; выключенный профиль брандмауэра или сторонний
брандмауэр снимал замок вовсе. Запрет в своём подслое от этого не зависит.
Цена прежнего пути тоже мерилась: метла PowerShell ~1,6 с, каждый `netsh`
~90 мс, `Get-NetAdapter` ~1,9 с; теперь замок — одна транзакция в
миллисекунды, и живой путь не запускает `netsh` ни разу (сторож —
`the_live_path_never_shells_out_to_netsh`).

Два свойства стены обязаны держаться, и оба со сторожами. Широких пропусков в
замке нет: каждый пропуск сужен приложением, флагом петли или протоколом с
портом, а один лишь адрес источника сужением не считается
(`the_lock_has_no_wide_permit`). И машина под замком остаётся
адресуемой — петля, DHCPv4/v6 и NDP пропущены, иначе она теряла бы и пробу
службы на `127.0.0.1`, и адрес на первом же продлении аренды, и шлюз по IPv6
(`the_lock_keeps_the_machine_addressable`). Личность фильтра — детерминированный
ключ из канонического описания (`filter_keys_are_stable_and_distinct`), а
набор в ядре сравнивается с желаемым по ключам: метлы нет, неизменившееся не
трогается, а имя фильтра в личность не входит (`the_name_is_not_the_identity`).
Транзакция одна на всё, поэтому окна между постановкой запрета и пропусков не
бывает, а на ошибке откатывается целиком. Фильтры постоянные: динамические
уходили бы вместе с процессом, то есть упавшая служба открывала бы сеть;
постоянные переживают и падение, и перезагрузку, и снимает их только явный
`apply` с пустым набором или `forget()` (деинсталляция).

На Linux то же самое свойство даёт сама nftables: `accept` в базовой цепочке
не отменяет другие цепочки на том же хуке, а `drop` окончателен, — значит
`policy drop` в нашей единственной таблице (`core_filter::linux`) запирает
машину, не трогая ни одного чужого правила. Замок — это постановка таблицы
целиком одной транзакцией `nft -f`, снятие — её удаление; чужой политики тут
нет и возвращать нечего, а раз `nft` транзакционен, сиротам просто негде
накопиться. Пропуск sing-box (по uid) встаёт в той же транзакции, что и сам
замок, — окна без пропуска между постановкой замка и разрешением ему сети здесь
не бывает; на Windows его тоже нет с тех пор, как стена переехала в WFP (раньше
там были два вызова `netsh` подряд).

Юнит `installer/proxybox.service` поднимает службу под root — без прав TUN и
nftables не работают — и требует `SIGTERM` на остановку: снятие правил висит
на обработчике, а `SIGKILL` оставил бы машину запертой до следующего старта.
Блок fail-closed в `scripts/e2e.sh` (под root, job `linux` в CI) — первая
сквозная проверка самого инварианта, а не только пути до узла: посторонний
процесс (другой uid, не служба и не sing-box) обязан достучаться до внешнего
адреса, пока замка нет, и не достучаться, пока туннель мёртв.

Пропусков три вида, и каждый узкий:

1. `sing-box.exe` — в той же транзакции, что и сам запрет, и до запуска
   процесса, иначе туннелю нечем подняться (`core_filter::apply`);
2. выбранные приложения — только по подтверждённой пробе;
3. `svchost.exe` UDP/53 — иначе заперт `dnscache`, и имена не разрешаются ни у
   кого, включая выбранных (сторож — `the_names_gap_is_only_dns`).

Это пропуска приложений. Рядом стоят служебные, без которых запертая машина
перестаёт быть машиной: петля, DHCPv4/v6 и NDP
(`the_lock_keeps_the_machine_addressable`). Они не про отбор и ничьего
трафика в открытую сеть не выпускают.

Пропуска (2) и (3) привязаны к адресу источника туннеля
(`Cond::LocalAddr(core_tunnel::TUN_ADDR)`), и это и есть «приложение не может
уйти напрямую»: пакет с физического интерфейса под правило не подпадает и
попадает под общий запрет. Тем же закрывается IPv6 — адреса v6 у нашего TUN
нет, и пропуски приложений ставятся только на `ALE_AUTH_CONNECT_V4`. Сторож
— `the_pass_is_bound_to_the_tunnel_address`; снимут привязку, и «нет
возможности» превратится в «мы попросили не уходить».

Выбранное приложение, чей путь стене не удалось превратить в идентификатор
приложения (WFP принимает путь только как существующий файл), пропуска не
получает — а замок и пропуска остальных всё равно встают. Ошибка одного пути не
должна ни ронять транзакцию, ни оставлять машину без стены: на первой
постановке откат транзакции означал бы отсутствие замка вовсе, то есть белый
список настежь. Так было бы на живой машине разработчика — путь
`…\app/ChatGPT.exe` со смешанными разделителями ронял `netsh`; разделители
теперь приводятся к `\` до WFP (`a_mixed_separator_path_reaches_wfp_with_backslashes`).
Служба пишет об отказе одну строку и запоминает применённое: повтор раз в три
секунды путь не починит. Не принят путь самого sing-box — запрет всё равно
встаёт, заперто всё, туннелю подняться нечем, и `apply` отвечает ошибкой:
закрыто, а не открыто. Сторож — `a_refused_app_path_never_takes_the_wall_down`.

Отдельного пропуска браузеру, которым оболочка открывает окна профилей, больше
нет. Сеанс разговаривает только с нашим прокси на `127.0.0.1`, а петлю стена
пропускает сама, для всех. Правило с `remoteip=127.0.0.1` и привязка его жизни
к сеансу (`Service::browser_pass`) ушли вместе с netsh; сторож
`a_dead_session_leaves_the_status_by_itself` следит, что оно не вернулось.
Цена открытой петли названа в `docs/limitations.md`: любой локальный процесс
может пользоваться нашим SOCKS на `127.0.0.1:48292`, как и раньше — Windows
Firewall петлю не фильтровал никогда.

В охвате «весь компьютер» пропусков приложениям нет: в туннель идёт всё, делить
некого, и стена нужна только на окно, пока туннель не подтверждён.

Пока sing-box не жив, TUN исчезает. Порядок в `Service::start()` обязателен:
`guard(true)` идёт впереди всего, включая убийство старого процесса, а
`guard(false)` — только после подтверждённой пробы в `supervise()`. Менять
местами нельзя, это и есть та самая дыра.

Подтверждает пробу не сам её успех, а совпадение `Service::generation`: порты у
нас постоянные, проба идёт без замка, и за её время туннель успевают
перезапустить — тогда ответ приходит про прошлый процесс и прошлый сервер.

`PROBE_EVERY = 3 с` — период пробы, а ширина окна утечки после падения процесса
— `DEATH_EVERY = 200 мс`: живость стоит одного `try_wait`, проба — похода в сеть,
и связывать их одним периодом значило платить за окно утечки временем сетевого
запроса. Наблюдатель за смертью только запирает и никогда не поднимает туннель
(`the_death_watch_only_blocks`): перезапуском заведует одна ветка `supervise`, и
вторая точка перезапуска — это два sing-box на один TUN и один `singbox.pid`.
В белом списке окна утечки по смерти процесса нет вовсе: запрет стоит всё время,
пока включён приватный режим, и умерший туннель лишь снимает пропуска
выбранных (наблюдатель делает это за те же 200 мс, но сеть при этом не
открывается, а закрывается). В охвате «весь компьютер» стена до подтверждения
стоит, а после него снята, и по смерти процесса её ставит наблюдатель — вот
остаток в `DEATH_EVERY`. Закрыть его целиком можно, держа запрет и там
постоянно, но это цена всей машине, и пока она не заплачена: потолок —
`ponytail:` в шапке `core-filter`, разбор в `docs/wfp.md`. Уводить из туннеля
при этом некого: маршрута мимо него в конфиге нет.

`PROBE_TIMEOUT = 8 с` — сколько проба ждёт ответа, и он обязан быть больше
`SINGBOX_DIAL_TIMEOUT = 5 с`, столько ждёт дозвона наружу сам sing-box (замерено
по его журналу: `dial tcp …: i/o timeout` приходит ровно на `5.0s`). Пока оба
ждали по пять, это была гонка двух таймеров, которую проба чаще выигрывала:
свой отсчёт она начинает, отправив запрос, а sing-box — получив его. Одно и то
же событие показывалось в ленте двумя лицами — то «не пропустил соединение (код
1)», то голое `os error 10060`, непереведённое, потому что это строка Windows. И
выигранная гонка не оставляла причины вовсе: оборванный на середине дозвон не
пишет `outbound/…`, то есть `last_failure` тянуть нечего. Сторож —
`the_probe_outwaits_singbox`. Плата — до трёх лишних секунд, с которыми
замечается уже мёртвый туннель; утечки в них нет (маршрута мимо туннеля в
конфиге не осталось), а смерть процесса ловит `DEATH_EVERY`, а не проба.
Те же три секунды платит и прогон профилей на каждом мёртвом узле — тот ходит
той же пробой. Живых это не касается вовсе, а разводить два срока ради
подписки, где мертвы все, значило бы завести вторую величину, которую надо
держать согласованной с первой.

`PROBE_MISSES = 3` — сколько промахов подряд означают «туннеля нет». Один не
означает ничего: проба — это новое TCP-соединение к серверу каждые три секунды,
самая хрупкая связь из всех, что у нас есть, и под потерями пакетов отваливается
она, пока живые соединения через тот же туннель идут как шли. Запертый на первом
промахе брандмауэр рвал именно их — SSH, загрузки, звонки, — и не закрывал при
этом ничего: маршрута мимо туннеля в конфиге нет вовсе, а смерть процесса ловит
`DEATH_EVERY` и запирает по-прежнему мгновенно. Терпение касается только
подтверждённого туннеля: пока он не подтверждён, выбранные приложения и так
заперты, рвать нечего, а лишние полминуты в «Подключении» прятали бы от человека
мёртвый узел. Плата — до полуминуты, которые мёртвый туннель показан живым, и
размен сознательный: поздний замок стоит приложениям отказов, которые они
переживут сами, а ложный — оборванного соединения, которое человек
восстанавливает руками. Сторож —
`a_single_missed_probe_does_not_cut_the_selected_apps`.

Причина, дотянутая в ленту из лога, помечена «последнее от sing-box», и это не
вежливость: свежесть её ничем не подтверждена. Пока проба переживает дозвон,
ответивший sing-box успевает и записать, но зависший — нет, и последним в логе
останется отказ получасовой давности. Названная последней, она остаётся
подсказкой; выданная за причину, отправила бы искать не то.

Первая проба после запуска идёт вперёд наблюдения за смертью (`probe_now`), и
это не про окно утечки, а про обратное: пока туннель не подтверждён, выбранные
приложения заперты, и ждать конца круга значило держать их без сети три секунды
при уже живом туннеле. Живость к этому моменту проверена самим запуском —
`Process::start` дождался готовности и убедился, что процесс не умер сразу.
Готовность — не часы: раньше стояла фиксированная пауза `STARTUP_GRACE` в
400 мс, теперь start опрашивает (`STARTUP_STEP` 25 мс), и готов sing-box, когда
mixed-порт принимает TCP и, если в конфиге есть TUN, наш `TUN_ADDR` уже
назначен (привязка UDP-сокета к нему удаётся только тогда). Потолок ожидания —
`STARTUP_LIMIT` (3 с): вышли живыми — тот же исход, что давала пауза, дальше
решает проба. Пол — `STARTUP_FLOOR` (200 мс), и он не украшение: порт может
держать чужой процесс, `connect` к нему удастся, хотя наш sing-box на `bind`
уже падает, — без пола занятый порт читался бы готовым туннелем, а повтор по
`port_was_taken` не получал бы ошибки. Сторож — `start_waits_for_readiness_not_a_clock`,
рядом `start_reports_immediate_death`.
Флаг обязан сниматься тем же чтением: оставшись взведённым, он превратил бы
наблюдателя в пустышку навсегда, то есть окно после смерти процесса стало бы
бесконечным. И читаться он обязан **внутри** цикла кругов, а не на входе в
наблюдение: взводит его `Service::start()` из чужого потока, а цикл занимает все
три секунды из трёх — прочитанный только на входе, флаг почти никогда там и не
застаётся. Так и было, и сокращал он не ту паузу: текущий круг досыпал до конца,
первая проба ждала до `PROBE_EVERY`, а флаг съедало следующее ожидание — то
самое, которое ждать как раз и должно. Сторож — тот же
`the_death_watch_only_blocks`.

## Контракт службы

`core-ipc` — построчный JSON: одна строка запроса, одна ответа (поэтому ответ
обязан быть без `\n` — сторож `single_line`). Транспорт на Windows — только
именованный канал с ACL; вне Windows — unix-сокет
`/run/proxybox/service.sock` (путь переопределяет `PG_SOCKET`) в каталоге
`0750 root:proxybox`. Отката между ними нет ни там, ни там: на чужой платформе
на том конце не служба, а сокет ограничить некому. Права в обоих случаях даёт
членство — в «интерактивных пользователях» на Windows, в группе `proxybox` на
Linux, — и различает оно пользователя, а не программу. Клиент открывает
именованный канал с `SECURITY_ANONYMOUS`: имя свободно до старта службы, и
подставной сервер иначе получил бы токен клиента.

Группу `proxybox` заводит `.deb` (`installer/postinst`). Без пакета —
установка из исходников — каталог сокета остаётся за одним root: служба
слушает, но управляет ею только root; `chgrp` на несуществующую группу служба
считает не отказом, а сообщением «пакета ещё не было»
(`crates/core-ipc/src/unix_socket.rs`).

Кто на том конце, служба спрашивает у канала (`Stream::peer` →
`GetNamedPipeClientProcessId`) или у сокета (`SO_PEERCRED`) и называет его в
журнале, если разрушающую команду прислал не свой (`note_caller`, `foreign` —
свой лежит в одной папке со службой). Это след, а не право: список доступа
различает пользователя, а не программу, и запусти чужая программа нашу же
консоль — отбор по образу пропустил бы её не глядя. Разрушающие команды
перечислены закрытым `match` без запасной ветки (`changes_the_machine`): новая
команда обязана получить ответ на этот вопрос осознанно, а чтение следа не
оставляет вовсе — статус спрашивают каждые две секунды. Сторож —
`a_command_from_a_stranger_is_named_in_the_journal`. Порты: 48292 mixed/SOCKS
(проба и headless), 48293 Clash API (счётчики).

Новая команда — вариант `Request`/`Response` в `core-ipc`, ветка в `handle()`
службы и тип в `ui/app-shell/src/platform.ts`. Забыть нельзя ничего: ветку
требует исчерпывающий `match`, а имена фронтенда сверяет с самим перечислением
`the_frontend_speaks_the_same_names` — он же ловит переименование, молчащее с
обеих сторон. Полноту `roundtrip` сторожит он же, изнутри теста.

CLI (`crates/pg-cli`) — по желанию: не всякая команда нужна в консоли, и
`Icon`, `RemoveApp`, `RemoveProfile`, `RemoveProfiles`, `RemoveSubscription`,
`EditSubscription`, `ExportLinks`, `SetOrder` в ней и не заведены.

Порт службы продублирован ещё и в `ui/app-shell/vite.config.ts` (мост
браузер→служба для разработки без Tauri) — сверяет `the_dev_bridge_knows_the_port`.

Привилегии только в службе. GUI (`src-tauri`) и CLI — тонкие клиенты `core-ipc`
без собственного состояния; логике в них не место. Их зависимости приколочены
храповиком `the_clients_stay_thin`: `core-config` или `core-filter` у клиента —
это разбор чужих ссылок и правила брандмауэра в процессе пользователя. Что уже
позволено (`core-tunnel`/`core-filter` в `doctor`, `core-apps` в оболочке) —
записано в самом сторо́же, новая зависимость роняет его.

## Языки

Языков шесть: `ru`, `en`, `fa`, `zh`, `tr`, `id`. Русский — исходный: на нём
пишут код, и он же служит ключом. Перечисление `Lang` и есть их список, рядом
лежит `LANGS` для перебора.

Набор выбран не на глаз: персидский, китайский и индонезийский стоят во всех
трёх сопоставимых клиентах (Hiddify, v2rayN, Clash Verge Rev), турецкий — в
двух. Языков, которых нет ни у кого из них, здесь заводить незачем.

Строки службы и клиентов лежат в `core-ipc::dict` таблицами «русский →
перевод», по одной на язык, плюс `dict::ALL` со всеми разом. Ключ — сама
русская фраза, поэтому таблицы RU не существует, а ненайденный ключ отдаётся
как есть: незаполненный перевод превращается в читаемую фразу, а не в пустоту и
не в `err.no_profile`. Откат двухступенчатый и вынесен в `lookup`: сначала
английский, потом ключ. На английский, а не сразу на русский, — пришедшему за
китайским латиница ближе кириллицы; отдельной функцией — потому что дырку в
статической таблице для проверки не завести, сторож полноты её не пустит, а в
`lookup` достаточно передать пустую (`a_hole_in_a_table_falls_back_to_english`).

До этого оба варианта стояли прямо в вызове (`t(ru, en)`), и это было честнее к
читателю кода: текст был там же, где им пользуются. Разменяли это на одно
свойство — добавить язык теперь значит добавить таблицу, ветку в `translate` и
экран помощи; в прежней схеме каждый новый язык означал правку всех ста
пятидесяти восьми мест.

`set_lang` кладёт вариант числом (`as u8`), а `lang()` разбирает его таблицей —
две записи одного порядка объявления, и разъезжаются они молча: язык просто
начинает означать соседний. Сторож — `every_language_survives_a_round_trip`.

Отсюда два правила, и оба со сторожами:

- перевод обязан быть во **всех** таблицах, и ключ обязан быть строковым
  литералом прямо в вызове. Компилятор это больше не проверяет: раньше вызов
  без английского не собирался, теперь он молча покажет русский — тому, кто
  русского не знает. Сторож `every_line_has_its_translation` вычитывает
  литералы `t("…")` и `tf!("…")` из исходников всех крейтов **и оболочки** и
  требует каждый в каждой таблице `dict::ALL`; он же заворачивает вызов, у
  которого первым аргументом стоит не литерал (собранная в рантайме строка
  ключом быть не может), таблицу с ключом, которого в коде нет, и таблицу,
  разошедшуюся с остальными длиной или порядком. Оболочка тут нужнее всех:
  `src-tauri` вне воркспейса, и `cargo check --workspace` её не собирает вовсе —
  пропущенный перевод в ней не всплыл бы до сборки на Windows;
- список языков обязан совпадать со списком в окне. Коды языков фронтенд пишет
  строками сам, компилятора у него нет, и язык, известный службе и неизвестный
  окну, — это пункт, которого нет в настройке: `SetLang` уйдёт, служба
  переключится, а выбрать обратно будет нечем. Сторож —
  `the_frontend_knows_the_same_languages`, он же требует подписи `langRu`,
  `langEn`, `langFa`, `langZh`, `langTr`, `langId` во всех словарях окна.

Подстановка — `tf!("нет профиля «{}»", name)`, и только `{}` по порядку:
`format!` требует литерал на этапе компиляции, а перевод приезжает из таблицы в
рантайме. Форматов вроде `{:>8}` тут нет и не нужно — это строки для человека, а
не колонки отчёта; `{:?}` передают готовой строкой. Лишнее место `fill` оставляет
швом, а не съедает: расхождение ловит сторож, но если оно доехало, шов виднее
пропажи.

Двух вещей в таблицах нет намеренно. Экран помощи CLI — не строка, а вёрстка, и
лежит константами `USAGE_RU`, `USAGE_EN`, `USAGE_FA`, `USAGE_ZH`, `USAGE_TR`,
`USAGE_ID`; `match` без запасной ветки требует написать его на новом языке
осознанно. И строки окна: они живут своими словарями в
`ui/app-shell/src/i18n.ts`, каждый типизирован как `RU`, а `DICT` объявлен
`Record<Lang, Strings>` — поэтому и дырку в словаре, и забытый язык не даёт
завести `tsc`; сторож нужен службе, а не окну.

Справа налево пишется только фарси; китайский, турецкий и индонезийский
раскладку не трогают вовсе. Направление ставится один раз на корне документа
(`document.documentElement.dir` в `App.tsx`), а не по панелям: раскладка тут вся
на flex и grid и переворачивается сама. Отсюда правило — штучные отступы обязаны
быть логическими (`ps-`/`pe-`/`start-`/`border-s`), физических `pl-`/`left-` в
разметке не осталось ни одного. Трёх мест это не берёт, и все помечены на месте:
сдвиг на полразмера (`-translate-x-1/2` у точки журнала и у полоски выбранной
вкладки — логических translate не бывает), тумблер (ручка едет сдвигом) и маска
карты (`[dir="rtl"] .st-map`, `.fly-map`): у градиента направление задаётся
углом, а угол логическим не бывает. Саму карту не зеркалим: это карта, а не
раскладка, и Европа в фарси остаётся слева от Азии. Меню под кнопкой (чип
охвата) якорится начальным краем кнопки, а не физическим левым (`fromStart` у
`Menu` в `ui.tsx`): справа налево оно растёт от её правого края внутрь окна;
меню по правой кнопке мыши остаётся там, где курсор.

## Что легко сломать

- Список приложений и охват правятся только через `Service::edit()`, и туннель
  он не трогает вовсе: конфиг о списке и охвате не знает, а перезапуск ради
  галочки оборвал бы всё живое — SSH, загрузки, звонки — и вдобавок запер бы
  выбранные приложения на время подтверждения пробы. Правка переставляет только
  фильтры стены (`refence()` → `guard()` → `core_filter::apply`, одна транзакция
  WFP), а `guard` идемпотентен: он помнит применённое в `Service::applied` и
  молчит, когда менять нечего. Сторож —
  `editing_the_list_never_restarts_the_tunnel`, он же следит, что `reapply`
  не завёлся снова. `Service::applied` помнит охват, замок и список приложений
  разом (пропуска браузера в нём больше нет) — иначе фильтры прошлого состояния
  остались бы висеть.

  Но «молчит, когда менять нечего» он выясняет, уже посчитав, с чем сравнивать,
  а считает он `selected()` — то есть `canonicalize` на каждое выбранное
  приложение. Ответ диска между кругами не обязан быть тем же: exe, который
  прямо сейчас подменяет сам себя (так обновляются Chrome, Discord, Steam), на
  круг-другой не находится, путь из двух форм становится одной, и применённое
  перестаёт совпадать. В белом списке при поднятом туннеле применённое —
  `Fence::Allow`, и мнимая смена списка — это уже не метла по правилам машины
  (метлы нет), а транзакция WFP: фильтр пропуска снимается и ставится заново, а
  каждое добавление или снятие фильтра на `ALE_AUTH_CONNECT` заставляет Windows
  переавторизовать живые потоки. Дорого не время, а эта пересверка:
  обновляющееся приложение гоняло бы её каждые три секунды себе и всем соседям
  по списку, пока идёт обновление. Поэтому круг надзора переставляет правила
  не всегда, а на самом переезде пакета (`rebind_packages()` вернула `true`)
  или когда применённое неизвестно (`applied.is_none()` — старт службы или
  отказавшая транзакция, и повторить попытку больше негде). Сторож —
  `a_settled_list_is_not_refenced_every_round`.

  Из снятого круга следует правило: событие само отвечает за свои правила, а не
  ждёт, что их переставят попутно. Прежде так было с пропуском браузера; теперь
  его нет, но прополка живых сеансов в ответе на `Status` осталась — она
  нужна статусу (открытые окна не должны врать) и самому процессу (`Drop`
  умершего `Process` добивает его sing-box). Стену она не переставляет вовсе
  (сторож — `a_dead_session_leaves_the_status_by_itself`).
- Обновление подписки заменяет профили молча, а активный узел трогает только
  через `after_refresh()`: гасить туннель ради самой замены — значит на миг
  снять правила раньше, чем поднят новый sing-box. Фоновая сверка узел, который
  пропал, не превращает в выключенный приватный режим (`Active::Drop`).

  Тем же `after_refresh()` решается судьба узла, правленного руками
  (`edit_profile`): это то же самое событие — «узел под тем же именем стал
  другим», — и второй ветки с тем же решением быть не должно.
- Вставка разбирается **построчно**, а не по префиксу всего текста. Пока
  смотрели на первый префикс, вставка из двух адресов подписок уезжала в `fetch`
  целиком, вместе с переносом строки, — и человек получал «подписка не
  скачалась» на двух исправных панелях, а окно в это же время обещало «строк: 2
  — импортируются разом». Режет `split_paste()`, сторож —
  `a_paste_splits_into_lines`; JSON он не режет вовсе (адрес внутри конфига — не
  адрес подписки). Сеть по-прежнему до замка: `import()` берёт замок сам и
  ненадолго — на каждую закачку отдельно, потом на одну запись.
- Импорт отвечает счётом (`Response::Imported`), а не `Done`: вставили полсотни
  строк, приехало двенадцать — и до сих пор нельзя было спросить нигде, куда
  делись остальные, хотя причина у службы на руках. Причин едет пять, а рядом их
  общее число: обрезанный список без числа читается как полный — та же беда, что
  у соединений. Читает счёт то самое поле, куда вставляли: общая красная рамка
  наверху окна про пропущенные строки сказать не может.
- Тот же узел вторым профилем не заводится (`add_profiles`, сторож —
  `the_same_node_is_never_imported_twice`). `free_name` выдал бы ему свободное
  имя, и в списке оказались бы две строки, которые нечем различить: имя узлу
  пишет чужая панель, а не мы.
- В окно про узел уезжают имя, тип, `host:port` (`ProfileInfo`, считает
  `core_config::describe`) и флаг `plain` — трафик до сервера открытым
  текстом (`core_config::plain`). Ни пароля, ни ключа: статус
  окно спрашивает каждые две секунды, а подписка приносит сотни узлов. Узел
  целиком отдаётся отдельным запросом (`Request::ProfileNode`) и только на
  открытие формы правки да на «скопировать ссылку». Класть его в статус — это
  гонять ключи туда-обратно сотнями раз в минуту ради строки, которую читают
  раз в месяц.
- Ссылку узла (`core_config::share_link`) отдаём только сверенную: собранная
  ссылка тут же разбирается обратно и сверяется с исходным узлом до поля, а не
  сошлась — ссылки нет вовсе, и в поле правки остаётся JSON. Ссылка, тихо
  потерявшая поле (мультиплекс, ECH, свой transport), — это правка, которая
  выглядит удавшейся, а узел стал другим: ровно тем же тихим промахом был
  матчер по `process_path`. Сборка поэтому нарочно оптимистична — точность
  держит сверка, а не полнота `build()`. Сторож —
  `a_link_means_the_very_same_node`. Обратной двери у ссылки нет и не нужно:
  правку читает тот же `core_config::parse`, что и импорт, — `edit_profile`
  принимал её и раньше, показать было нечего.
- Узел из подписки не правится и не переименовывается (`edit_profile`, сторож —
  `a_subscription_node_is_never_edited`): её набор заменяет сверка целиком, и
  правка вернулась бы прежней ближайшим кругом. Удалить его при этом можно, и
  разница тут не в упрямстве: удаление сбывается сразу и целиком, а вернёт узел
  только следующая сверка — то есть обещание держится ровно до неё, и меню
  говорит об этом прямо (`removeFromSubHint`). Правка же не сбывается вовсе:
  строка возвращается прежней, ничего не сказав. Переименование своего профиля
  обязано перевесить всё, что смотрит на узел по имени: активный профиль,
  браузерные профили, измерения и звёздочку избранного. Сама звёздочка
  (`Saved::favorites`, `Request::SetFavorite`) лежит именами рядом с
  профилями, а не флагом внутри узла: узел из подписки сверка заменяет целиком,
  и флаг стирался бы каждым кругом — а отмечает человек не узел, а строку,
  которой пользуется. Профиль ушёл — звёздочка уходит с ним (прополка в
  `save()`), иначе вернувшийся под тем же именем чужой узел получил бы чужую
  отметку. Сторож —
  `a_favourite_follows_the_profile_and_not_the_node`.

  Не править узел на месте не значит не давать его поправить: меню узла
  подписки несёт «Изменить как свой» — та же форма правки, заполненная узлом,
  а сохранение идёт обычным `add-profile` и заводит копию своим профилем с
  названным именем (имя — фрагмент ссылки, `tag` в JSON или `ps` во вложенном
  JSON base64-vmess: окно раскрывает его, ставит имя и собирает обратно). Не
  изменили узел — отказывает та же дедупликация, что и у вставки
  (`the_same_node_is_never_imported_twice`), и форма говорит об этом словами
  («такой узел уже есть»), а не закрывается, как будто копия появилась.
  Дедупликация **не смотрит на имя**: узел из JSON несёт его в `tag`, из
  ссылки — нигде, и сравнение «до поля» считало бы переименованную копию
  другим узлом — «Изменить как свой» с одним лишь новым именем заводил бы
  двойника, и отказ зависел бы от того, чем узел завели. Сравнивает
  `core_config::same_node` (поле `tag` не в счёт; других полей-имён разбор в
  узел не кладёт), сторожа — `a_renamed_json_copy_is_still_the_same_node` и
  `a_node_is_the_same_under_another_name`. Ошибка формы правки профиля и
  подписки показана один раз — в самой форме: `Act` принимает `{ local: true }`,
  и общая рамка наверху окна такой отказ не повторяет.
- Подписку правят командой `EditSubscription { url, new_url, name }`, и
  порядок в ней обязателен: новый адрес качается первым и **до** `svc.lock()`;
  не скачался, узлов нет, адрес занят другой подпиской — ошибка, а в состоянии
  не изменилось ничего. Только удачный ответ переезжает на место старой записи
  (тот же номер в порядке групп, подпись, остаток), а узлы заменяет тот же
  `apply_subscription`, что и сверка (`subscribe` — это закачка плюс он), с тем
  же решением о судьбе активного узла (`after_refresh`). Меняется только
  подпись — сети нет вовсе. Смена адреса пишет в журнал строку «адрес
  подписки «…» изменён», названную подписью (без неё — хостом): полный адрес
  несёт токен панели, а журнал лежит на диске. Окно — небольшое окно «Изменить
  подписку» (`SubEdit`), одно на карточку полосы, заголовок группы и правую
  кнопку: поле имени в строке адреса не вмещало. Сторож —
  `editing_a_subscription_replaces_it_in_place`.

  Два следствия из того, что `apply_subscription` один на сверку и на правку.
  Плановая сверка подписку обновляет, а не заводит: адрес, которого уже нет в
  `subscriptions` (убрали `RemoveSubscription` или перевезла правка, пока
  качалось — список адресов круг снимает под замком, а качает без него),
  пропадает молча, без записи и без строки в журнале; нажатие человека адрес
  заводит как прежде. Сторож —
  `a_late_refresh_never_resurrects_an_edited_subscription`. И замер держится
  на имени узла, а панель отдаёт то же имя другому узлу: узел сменился или
  исчез — его замер уходит, тот же узел замер сохраняет (иначе «Удалить
  нерабочие» снесла бы узел, которого никто не мерил). Сторож —
  `an_edited_subscription_does_not_inherit_dead_probes`. «Удалить подписку» (бывшее
  «Отписаться») стоит в том же меню подписки, а значит во всех трёх местах:
  «⋯» заголовка, «⋯» карточки и правая кнопка.
- Список профилей выделяется несколькими строками (Ctrl/⌘+клик, Shift+клик
  диапазоном, флажок на месте флага по наведению и по фокусу, Esc, Ctrl+A по
  видимым). Выделение — состояние окна: служба о нём не знает. Держится оно
  только на видимых строках: профиль исчез, строку спрятал поиск, отбор полосы
  подписок или свёрнутая группа — она выпадает из выделения (пачка обязана
  действовать на то, что человек видит). Ctrl+F при выделении снимает его и
  переводит фокус в поле поиска — на время выделения поля на экране нет;
  Ctrl+V по-прежнему открывает импорт. Нажатие по строке сперва спрашивает
  выделение и только потом включает узел (иначе Ctrl+клик посреди выделения
  включал бы туннель), перетаскивание при выделении выключено, а панель
  инструментов уступает место панели выделения («Выбрано N», «Проверить»,
  «Экспорт», «Удалить», «⋯», ✕). Сторож — `a_selection_outranks_turning_a_node_on`.
- Пачка удаляется одной командой `RemoveProfiles { names }`: одна запись и
  одна строка в журнале с числом, судьба активного узла и сеансов браузера —
  у `forget_profile`, той же, что у одиночного удаления; неизвестные имена
  молча пропускаются (список собирало окно, а сверка могла убрать часть).
  Окно спрашивает, когда в пачке есть активный профиль, узел под окном
  браузера или узлы подписок (те вернутся со следующей сверкой), и всегда —
  когда в пачке два профиля и больше (число в заголовке); «Удалить
  нерабочие» спрашивает всегда. Нерабочий — измеренный и не ответивший
  (задержки нет, причина есть); неизмеренный не нерабочий никогда, пока идёт
  прогон — пункт заперт. Сторож — `bulk_removal_is_one_save_and_one_journal_line`.
- «Проверить» выделенных — тот же `TestProfiles`, у которого `only` стал
  списком имён; единственный прогон за раз держит прежний `PROBE_LOCK` и
  `Status::testing`. Экспорт — `ExportLinks { names }`: только сверенные ссылки
  (`core_config::share_link`) и число тех, для кого точной ссылки нет; служба
  ничего не пишет и не логирует, в буфер обмена ссылки кладёт окно и нигде их
  не хранит. Доступен для выделенного, для подписки целиком и для всех.
  Сторож — `export_gives_verified_links_and_counts_the_rest`.
- Срок сверки — настройка (`Settings::refresh_hours`), и ноль в ней не живёт:
  нулевой срок означал бы поход по всем подпискам каждый круг потока, то есть
  раз в пять минут. Подрезают его дважды — в `SetSettings` и в `refresh_every()`:
  `state.json` правят руками. Сторож — `the_refresh_period_is_never_zero`.
  Выключается сверка флажком, а не сроком.
- Всё, что надолго уходит наружу, разбирается в `handle()` **до** `svc.lock()` —
  так сделана подписка. Иначе окно на все двадцать секунд перестаёт получать
  статус: замок один на состояние и на обработку команды. И не только окно —
  `supervise` и `watch_for_death` берут тот же замок, то есть смерть sing-box
  замечается не за `DEATH_EVERY`, а когда команда закончится.

  «Наружу» — это не только сеть. Иконка (`Request::Icon`) достаётся из файла по
  пути из запроса, автообнаружение (`Request::Discover`) обходит реестр, меню
  «Пуск» и `WindowsApps`; состояния службы не нужно ни той, ни другому. Иконка
  из них хуже: её спрашивают не один раз, а по одной на каждое приложение
  списка и залпом, как только открыли вкладку, — соединение у каждой своё
  (поток на подключение), так что весь залп выстраивался в очередь к замку, а
  один путь на отвалившейся сетевой шаре добавлял к этому таймаут SMB. Сторож —
  `the_lock_is_never_held_through_a_walk_of_the_disk`: он сверяет текстом, что
  обе команды встречаются в `handle()` раньше, чем тот берёт замок. Список
  соединений и прогон профилей отпускают замок руками, уже взяв его, — под
  сторожа они не подпадают, и добавить туда третью такую команду он не помешает.
- Соединения (`Request::Connections`) служба не хранит и не кэширует: список
  собирается на запрос и умирает вместе с ответом. Кэш «на двух клиентов» — это
  уже хранение трафика, а его продукт не ведёт. Порт clash-api снимается под
  замком, а сам запрос идёт без него: на том конце sing-box, и его молчание
  стоило бы окну всего статуса. Список режется сотней по громкости, поэтому
  утечка обязана ехать впереди неё (`leaks_first`, сторож —
  `a_leak_is_never_truncated_away`): выбранное приложение, ушедшее напрямую, —
  это пара килобайт, и без подъёма оно тонуло бы под чужим торрентом, то есть
  панель теряла бы единственное, ради чего её открывают. Кто держит соединение,
  служба тоже считает сама — по локальному порту (`core_apps::port_owners`,
  сторож `the_process_is_found_by_the_local_port`). Раньше имя приходило от
  sing-box в `metadata.processPath`, но заполняет он это поле, только когда в
  маршрутизации есть правило по `process_path`; вместе с матчером по процессу
  поле опустело для всех соединений разом, и панель писала «без процесса»
  каждой строке. Снимок таблицы сокетов берётся раз на запрос и только пока
  панель открыта — sing-box за то же платил снимком на каждое соединение
  машины, и это ровно тот расход, из-за которого матчер убирали. Столкнувшийся
  порт разводится по локальному адресу (`core_apps::Owner`, сторож —
  `a_clashing_port_has_no_owner`), и адрес спрашивается только у него: снимок
  сокетов берёт Windows, а `sourceIP` называет sing-box, и сверять их всюду
  значило бы поставить всю колонку в зависимость от совпадения, не проверенного
  на живой машине. Что неразличимо и с адресом, остаётся без имени: назвать
  соединение чужим процессом хуже, чем не назвать. Ищет владельца замыкание из
  службы, а не карта: `core-tunnel` не должен из-за одной колонки зависеть от
  `core-apps`. Считает утечку служба и
  только она (`Conn::leak`). Срабатывать ей теперь почти не на чем: под
  `final: proxy` всё, что sing-box вообще видит, идёт в туннель, а по-настоящему
  утёкшего соединения он не увидит вовсе. Оставлено страховкой на случай, если
  маршрут мимо туннеля когда-нибудь заведётся снова. Скорость канала
  окно рисует графиком из счётчиков статуса у себя же (`useRates` в
  `StatusBar.tsx`) и держит её в шапке, а не во вкладке соединений: скорость —
  про сам канал, и смотрят на неё там же, где написано, поднят он или
  перерублен. Внутри шапки это карточка «Скорость» (вторая в ряду из трёх):
  подпись с бледным промежутком, который график держит, текущие ↓ и ↑ крупными
  числами, под ними колодец с одним графиком на обоих направлениях и с
  бледными линиями шкалы, а внизу мелкая справка «за сеанс ↓ ↑». Масштаб у
  двух линий общий: разные шкалы в одном колодце читаются как одинаковая
  нагрузка при десятикратной разнице.
  Сорок снятий счётчиков в памяти окна (снимает их служба раз в
  `PROBE_EVERY × TRAFFIC_EVERY`, то есть ~15 с, — сорок отсчётов держат около
  десяти минут) — вся история, какая у продукта есть; в узком окне остаются
  числа, колодцев нет. Подпись не обещает числа: прежние «90 с» из словаря
  были вдесятеро короче правды, — а считается от самих отсчётов на экране, по
  первой и последней отметке `traffic_at` (`spanSeconds`), и формат — минуты
  или секунды на каждом из шести языков (`histSpan` — функция от секунд, не
  строка); пока отсчётов меньше двух, подписи нет. Сторож —
  `the_speed_history_spans_what_its_label_says`. В плашке из трея — текущая скорость и
  тот же график вместо итогов сеанса. Задержка — третий блок: крупное число
  с доездом, под ним колодец с полосками последних замеров (`useLatencies`) и
  справка «мин … макс» по ним — тоже память окна, сброс при падении туннеля,
  без своего опроса и без службы.
  Считается она по `Status::traffic_at` — отметке снятия счётчиков, а не по
  такту опроса: служба ходит за ними реже, чем окно спрашивает статус, и те же
  числа, поделённые на две секунды, дали бы нули со всплеском вместо линии.
  Сторож — `the_speed_is_counted_from_the_service_clock`.

  Отбор по строке (`Request::Connections { filter }`) считает служба, и порядок
  в ветке обязателен: отбор, потом `leaks_first`, потом обрезка. Список режется
  сотней по громкости, поэтому отбор, сделанный окном, искал бы среди
  показанных — и на тихое соединение, ради которого поиск и открывают, отвечал
  бы «ничего не нашлось» при живом соединении. Это тот же тихий промах, из-за
  которого утечка едет впереди обрезки. Рядом со списком поэтому два числа, а
  не одно: с непустым отбором «всего» — это вся машина, а не то, что искали.
  Сторож — `a_filter_is_applied_before_the_cut`.

  Выбранность строки считает служба (`Conn::picked`), а не окно, и по той же
  причине, что и утечку: форм у пути до двух, а в списке приложений живёт одна.
  Своя сверка в окне предлагала бы «добавить в белый список» тому, что там уже
  есть, — то есть заводила бы второй экземпляр того же exe. По той же причине
  `AddApp` сверяет путь через `knows()`, а не побайтово: путь приходит со
  стороны — из панели соединений его пишет файловая система, из реестра
  установщик.

  Панель — настоящая таблица: шапка (липкая) и пять колонок одной сетки
  `.conn-row` — путь, приложение, адрес (на остаток, моноширинный), ↓ и ↑
  (правой колонкой, моноширинные). Слово в колонке пути стоит у **каждой**
  строки: «туннель» бледным, остальные — своим тоном (исключение — акцентом,
  молчит — янтарным, утечка — красным полужирным, «напрямую» у разобранного
  самим sing-box — серым). Пока слово писалось только у не-туннеля и шло
  префиксом перед именем, оно сдвигало всё правее, и ни числа, ни адреса не
  вставали в столбец. «Молчит» — не маршрут, а свойство туннельного
  соединения, но в колонке пути оно занимает место слова «туннель». Кнопка «В
  исключения» стоит внутри ячейки адреса, а не отдельной колонкой: колонки
  чисел обязаны остаться на месте. Ниже 768 px адрес уходит второй строкой под
  приложение, а шапка теряет его заголовок. Меню по правой кнопке — во всех
  охватах: в белом списке и «весь компьютер» «в белый список» / «убрать из
  белого списка» (решает `picked`), в «Раздельно» — «пускать напрямую» /
  «вернуть в туннель» (решает список `direct_apps`, а не `picked`, который там
  всегда ложь), плюс «в исключения» у молчащей строки. Правка списка
  «напрямую» перезапускает туннель, поэтому уходит после вопроса; приложение,
  которого нет в общем списке, сперва заводится в него — иначе галочку, снять
  которую, было бы негде. Сторож — `the_connections_are_a_table`.
- Отбитых соединений в панели нет и быть не может: Windows останавливает их на
  `connect`, до sing-box они не доходят, а сокет не успевает попасть в таблицу
  сокетов — следа не остаётся нигде. Единственный способ их увидеть без своего
  WFP-callout — аудит WFP (событие 5157), то есть машинная политика аудита и
  каждый отбитый пакет машины в журнале безопасности навсегда: продукт завёл бы
  ровно тот журнал трафика, которого не ведёт, и обещание «нигде не
  сохраняется» стало бы ложью, невидимой из окна.

  Поэтому вопрос перевёрнут: не «что отбито», а «кто заперт»
  (`Request::Fenced`). Ответ выводится из уже известного и не заводит ни одной
  записи: запущенные приложения человека (тот же обход, что у автообнаружения,
  — `core_apps::running`) минус белый список. При включённом приватном режиме
  невыбранное приложение заперто по определению, а не по догадке; в охвате
  «весь компьютер» ответ пуст всегда, потому что делить там некого.

  Обещать этим списком «оно стучалось» нельзя: молчащее приложение выглядит так
  же. Разбирается запрос под замком ровно до `drop(s)` — как соединения, — а
  обход процессов идёт уже без него: под общим замком за ним встали бы и статус
  окна, и надзор за туннелем. Такт у него свой и вчетверо реже, чем у
  соединений: список меняется по запускам приложений, а не по секундам, и
  платить за него обходом всех процессов каждые две секунды незачем.
- Счётчики трафика забираются раз в `TRAFFIC_EVERY` кругов надзора, а не каждый.
  Clash API отдаёт итоги только в теле `/connections` — вместе со всем списком
  живых соединений и после него, так что оборвать разбор нельзя. Замерено на
  1.13.19: ~357 байт на соединение, 500 соединений — 178 КБ. Через туннель идёт
  вся машина в обоих охватах, и в патологии это десятки мегабайт на опрос
  каждые три секунды: надзор становится усилителем того самого расхода, который
  им же и меряют. Живости это не касается — она на `Process::alive`. Сторож —
  `the_counters_are_not_polled_every_round`. По той же причине ЦП меряют с
  закрытой панелью соединений: открытая опрашивает то же тело каждые 2 секунды.
- `Service::applied` помнит применённое к стене: без этой памяти надзор
  гонял бы транзакцию WFP каждые три секунды, а каждая переустановка фильтра
  на `ALE_AUTH_CONNECT` переавторизует живые потоки. Неудачу не запоминаем
  намеренно.

  Метлы, политики и возврата политики в живом пути больше нет, и это не
  экономия, а устройство стены. Набор в ядре сравнивается с желаемым по
  ключам фильтров (`filter_keys_are_stable_and_distinct`): лишнее снимается,
  недостающее ставится, неизменившееся не трогается, а потому и «метла по всем
  правилам машины» (PowerShell ~1,6 с на нажатие «Включить») не нужна — чужих
  правил в нашем подслое нет. Политика машины не меняется вовсе, значит и
  возвращать её после себя нечего: `blockoutbound` мы не ставим, а значит, и
  читать её перед замком незачем. Служба не вправе вернуться к этому (`policy_now`,
  `set_killswitch`, `set_fence`, `locked_by_us` из `core_filter` в ней
  запрещены) — сторож `the_netsh_migration_runs_after_the_wall_stands`.

  На Linux всё это и раньше было иначе: замок — своя таблица nftables, чужой
  политики служба не берёт (`core_filter::linux`), снятие замка удаляет таблицу
  целиком, и сиротам просто негде накопиться.

  Остался один след старой эпохи — и только на машинах, где стояла прошлая
  версия. Она держала замок политикой `blockoutbound` и разрешающими правилами
  `netsh` и записала прежнюю политику в `state.json`; всё это живёт в
  брандмауэре, переживая и перезагрузку, и обновление. Поэтому служба зовёт
  `core_filter::migrate_netsh` (`legacy.rs`) — метёт правила обоих префиксов,
  включая разрешение для sing-box, возвращает сохранённую политику (запасной
  путь — умолчание Windows) и очищает поле. Зовёт не `run()`, а
  `Service::leave_netsh()`, и только из удачной ветки `guard`: перенос обязан
  идти **после** того, как стена встала, а не после того, как её попросили
  поставить. Стоял он в `run()` за восстановлением приватного режима — и
  отказавшая на старте транзакция WFP (отвергнутый путь, лежащий BFE) снимала
  старый `blockoutbound`, когда нового замка не было, то есть открывала машину
  при включённом приватном режиме. Теперь не вставшая стена оставляет на месте
  старый замок. Поле `Service::legacy_policy` (бывшее `policy`) читается только
  здесь и в файл больше не пишется после переноса; флаг `legacy_pending`
  снимается на любом ответе, кроме отказа, а отказ повторится на следующей
  удачной постановке (одинаковую строку журнал не повторяет). Сторож —
  `the_netsh_migration_runs_after_the_wall_stands`; сам возврат политики,
  разбор её строки по закрытым спискам профилей и действий и «всё или ничего»
  по трём профилям — `the_lock_gives_back_the_policy_it_found`. На свежей
  установке цена переноса — пара запросов `netsh show rule`.

  Проверка чужих туннелей (`foreign_tunnels()`) — это поход в PowerShell
  (`Get-NetAdapter`, ~1,9 с), и стоит она после `guard(false)`, а не перед, и
  идёт своим потоком без общего замка: замок берётся лишь записать
  предупреждения, а `Up` ставится, не дожидаясь ответа. Иначе она лежала бы
  между подтверждённой пробой и открытием сети выбранным приложениям, пока окно
  ждало ответа на `Status`. Предупредить о чужом туннеле обязаны, задерживать
  этим сеть и статус — нет. Поток проверяет поколение: туннель, о котором речь,
  мог смениться за эти секунды. Сторож — `the_foreign_tunnel_check_never_delays_up`.
- Настройки службы приходят набором целиком (`Request::SetSettings`), и клиент
  присылает обратно то, что ему показали, — то есть уже перебитое окружением.
  Поэтому `handle()` возвращает перебитые поля к сохранённым: без этого
  `PG_PROBE`, выставленная в e2e, записалась бы в `state.json` навсегда с первой
  же правки любой другой настройки. Действующее живёт в `status.settings`,
  выбранное человеком — в `Service::settings`, и путать их нельзя.
- Ни одна настройка не перезапускает туннель — и не должна: путь к sing-box
  действует со следующего запуска, проба и страна со следующего измерения,
  сверка со следующего круга. Причина ровно одна: перезапуск ради настройки —
  это выбранные приложения без сети на ровном месте. Теперь то же верно и про
  список приложений с охватом — кроме «раздельно», чьи приложения и наборы
  правил стоят в конфиге: вход в него, выход и их правка идут через
  `restart_routing`. Так что поднимают туннель заново `Request::On`, смена
  профиля, `Request::SetBypass`, эти правки «раздельно» и ветка перезапуска в
  `supervise`. Исключения потому и не настройка: они живут в
  конфиге, а не в стене, и их правка — перезапуск через `start()`, то есть
  через `guard(true)` впереди всего; неизменившийся набор туннель не трогает
  (сторож — `a_bypass_edit_restarts_through_the_lock`). То же верно для
  самого `start()`: ничто в нём не возвращается раньше `guard(true)`, и
  проверка настроек «раздельно» стоит после замка и отказывает как отказавший
  запуск sing-box — с паузой повтора (`start_failed`, сторож
  `split_validation_never_runs_ahead_of_the_lock`). Добавленный набор правил без
  файла конфиг не меняет и туннель не перезапускает — его докачивает надзор.
- Картинка плиты состояния — плоская карта мира силуэтами стран
  (`WorldMap.tsx`), не глобус и не точечная сетка. Сетка из точек — текстура,
  одна на все VPN-клиенты, и по ней читалась только часть света; силуэт даёт
  страну выхода как знак: при перелёте окно приближает её так, что очертания
  узнаются, — Нидерланды, Япония, контур США. Увеличение выбирается по стране,
  а не задано числом: материковое кольцо занимает долю рамки (`fit`), иначе
  Россия не влезала бы, а Нидерланды были бы точкой. Кольцо, а не вся страна:
  у Нидерландов есть Карибы, у Франции — Гвиана, и по общей рамке они уезжали
  бы в океан.

  Заливка силуэта обязана носить состояние: сплошная тоном — канал несёт
  трафик; штриховка — заперто, и на подключении тоже (там тоже заперто); один
  контур — режим выключен (узел выбран, трафик через него не идёт). Это третий
  способ прочесть состояние после слова и цвета, единственный, который
  читается с карты боковым зрением. Решает `index.css` по `data-state`, узор
  штриховки живёт в `WorldMap.tsx` под фиксированным `HATCH_ID`: `fill:
  url(#…)` из CSS случайного `useId` не знает. Сторож —
  `the_exit_country_wears_the_state`.

  Данные собирает `scripts/worldmap.py` из Natural Earth 50m в `worldmap.ts`
  (проекция Миллера, целые единицы по 0.05°, Дуглас–Пекер с допуском,
  сжимающимся для малых колец, — 98 КБ, 40 в gzip), руками их не правят.
  Точка страны — `LABEL_X`/`LABEL_Y`, а не центр масс (у Норвегии и Чили он в
  море), ключ — тот же ISO-код, которым служба подписывает пробу
  (`Probe::code`). Своей страны человека на карте нет и не будет: спросить её
  можно только у стороннего сервиса, а без туннеля это выдало бы настоящий
  адрес.

  Движение двух родов, и разведены они по цене. Перелёт к стране — покадрово из
  JS и только на смене страны: силуэты — десять тысяч вершин, и кадр перелёта
  стоит их перерисовки, так что платим секундой, а не всё время; смена размера
  окна камеру только переставляет, без перелёта. Пульс точки выхода идёт всё
  время, пока туннель поднят, и потому обязан жить вне `<svg>`, своим
  HTML-слоем, и двигать только прозрачность и масштаб — внутри карты он

  заново.
- Аватарку браузерного профиля рисует окно (`look` и `Avatar` в `ui.tsx`) —
  три цветных пятна и первая буква имени. Алгоритм подсмотрен в arboweb: два
  хеша зерна дают тон, положение пятен и один из трёх шрифтов окна. Там пятна
  двигал шейдер, потому что аватарка дышала под курсором; у нас она стоит на
  месте, и три радиальных градиента со смешиванием `screen` CSS складывает сам.
  Канвы и WebGL тут нет и не надо: контекст рисования на каждую строку списка —
  дорого за неподвижную картинку.

  Пятна не расходятся по углам квадрата, как в оригинале (`0.2 + r * 0.6`):
  картинка обрезана в круг на тёмном окне, и пятно из угла остаётся почти
  целиком снаружи — полкружка сливалось бы с фоном. Из этого же следует цвет
  буквы: фон под ней всегда светлее её (замер по двадцати тысячам зёрен —
  яркость центра от 0.35 до 0.89), поэтому буква просто тёмная в тон пятнам, а
  ветки «чёрная или белая» нет — она не исполнялась бы ни разу. Прозрачность
  буквы 0.7 тоже замерена, а не подобрана на глаз: непрозрачная давала контраст
  6.6:1..15.6:1 и на светлых аватарках выжигала дыру, с прозрачностью выходит
  3.9:1..6.3:1 — верх притушен вчетверо, низ остался выше 3:1, которых требует
  крупный жирный знак. Ниже опускать нельзя: 0.5 даёт уже 2.5:1.

  Шрифты — три разных рода (антиква, узкий DIN, моноширинный), а не три
  гротеска: на одной букве Segoe UI и Bahnschrift различаются шириной, и
  только. Антиква и DIN названы в `FONTS` прямо, а не токеном темы: своего
  серифного стека у окна нет, а заголовочный стек окна с Bahnschrift ушёл на
  Segoe UI Variable — возьми аватарка его, и у всех уже заведённых профилей
  сменилась бы картинка. Georgia стоит на Windows со времён 2000; Times New Roman
  за ней — подстраховка на случай, если кириллицы в Georgia не окажется.

  Начертание тоже по зерну, и ровно два — 400 и 700 (`WEIGHTS`). Промежуточных
  нет намеренно: у Georgia всего два реза, и запрошенное 600 браузер отдаст либо
  тем же 700, либо подделает — две трети антиквенных аватарок вышли бы жирными,
  а разнообразия не прибавилось бы. Тянется вес **последним** из генератора: тот
  отдаёт числа по одному, и вставленный выше сдвинул бы весь хвост — у всех уже
  заведённых профилей разъехались бы и пятна, и шрифт. Новое поле сюда добавляют
  только в конец.

  Зерно — `BrowserProfile::icon`, и служба в него не смотрит вовсе: перекатывает
  его окно по нажатию на саму картинку в форме правки. Пусто — зерном служит имя,
  так ведут себя и профили, заведённые до появления поля. Из того же зерна растёт
  цвет, который окно передаёт оболочке строкой: им рисуется значок окна в панели
  задач (`core_apps::icon_bytes`). Значок остаётся плоским кружком — буква там
  требовала бы шрифта и растеризации в Rust, — поэтому берётся насыщенное пятно,
  а не то, что вышло в середине. Посчитанный в Rust второй раз, цвет разъехался
  бы на первой правке — и стал бы врать про то, какое окно чьё. Сторож —
  `the_profile_picture_grows_from_one_seed`.
- Удалённый браузерный профиль уходит в корзину (`Status::browser_trash`,
  `Service::trash_browser`), и его имя новому профилю не достаётся: каталог
  сеанса зовётся по имени (`dir_name`), и новый открылся бы с входами
  удалённого. Отказывает `set_browser` в службе, форма лишь говорит это
  раньше; сторож — `a_trashed_name_is_not_reused`. Стирание навсегда идёт в
  обязательном порядке: сперва `forget_browser` в оболочке, потом
  `PurgeBrowserProfile` — наоборот, и занятый окном каталог остался бы с
  входами без записи о том, чьи они. Клон входов не копирует: одни куки на два

  стирается оболочкой после закрытия окна и перед запуском, если окна нет
  (`waiting()`), — стирать каталог из-под живого браузера нельзя.
- Win32 для окна браузера живёт в `core-apps`, а не в оболочке, намеренно:
  `src-tauri` вне воркспейса, и `cargo check --workspace --target
  x86_64-pc-windows-msvc` его не трогает. Небезопасные вызовы, которые нигде не
  компилируются, кроме живой Windows, — плохая сделка.
- Личность окна Chromium делается адресом узла, `--user-agent`,
  `Accept-Language` через `Preferences` каталога сеанса и DevTools-каналом
  (`core_apps::cdp`): `Sec-CH-UA` под строку, часовой пояс и запрет
  геолокации. Канал — труба на унаследованных дескрипторах, а не порт отладки:
  к порту на петле подключится любой локальный процесс и заберёт куки. Новая
  цель запускается только после подмены, а отпущена обязана быть всегда —
  иначе вкладка висит пустой (сторож —
  `every_target_is_released_after_its_disguise`; живой Chrome —
  `a_live_chrome_takes_the_disguise`, только с `--ignored`). Не открылся
  канал — окно не открывается: без подмены оно показало бы настоящие пояс и
  местоположение. Canvas, WebGL, шрифты и число ядер не подделываются — только
  патченным Chromium; не добавляйте полей, которые ничего не делают.
  Одинаковый для всех отпечаток даёт движок Firefox (`Engine::Firefox`,
  `privacy.resistFingerprinting`): прокси у него в `user.js`, и три двери мимо
  узла — откат на прямое, системный резолвер и WebRTC — закрыты там же
  (сторож — `firefox_never_goes_around_the_proxy`). Движки окно пишет строкой
  (`the_frontend_knows_the_same_engines`).
- Каталог у сеанса браузера свой (`browser/<dir_name>`), и имя ему считает
  `core_ipc::dir_name` — одна функция на службу и на оболочку. Голой чистки
  символов мало: «a/b» и «a-b» дали бы один каталог, а каталог сеанса — это его
  `singbox.pid`, по которому `Tunnel::start` добивает предшественника. Два
  профиля молча гасили бы друг друга, как гасил каждый новый сеанс, пока
  каталог был общий.

  Отметка эта живёт ровно до остановки: убирает её `Tunnel::stop()`, а значит и
  Drop. Нужна она для одного случая — службу убили сигналом, Drop не отработал,
  и sing-box остался с поднятым TUN без присмотра. Погашенного нами добивать не
  надо, а номер его Windows отдаст кому-нибудь другому; проверка по имени в
  `reap_orphan` спасает от посторонней программы, но своих между собой не
  различает никак, и по переиспользованному номеру гасится соседний сеанс или
  сам общий туннель. Сеансов бывает сколько угодно, и каждый оставлял по
  отметке за закрытие. Убирает поэтому не вызывающий, а `stop()` — через него
  проходят все трое: прогон профилей, сеанс браузера и общий туннель. Сторож —
  `a_stopped_tunnel_takes_its_mark_with_it`.
- Продукт переименован из Privacy Gateway в proxybox, и четыре имени пережили
  бы переименование на живой машине, потому что живут не в коде, а в системе.
  Каждое снимается своей миграцией, и снимать сами миграции нельзя, пока на
  свете есть хоть одна машина с прошлой установкой.

  Правила брандмауэра: они остались только в миграции с netsh
  (`legacy.rs`, `migrate_netsh`), живого пути у них нет. Метла там метёт оба
  префикса (`LEGACY_RULE_PREFIX`, сторож — `the_broom_sweeps_the_old_name_too`)
  и заодно разрешение для sing-box (`the_broom_takes_the_singbox_rule_too`):
  наши старые правила разрешающие, запрещала политика по умолчанию, поэтому
  сирота не запирает приложение, а наоборот — пускает в туннель то, что человек
  из списка уже убрал, и делает это молча. Новая стена их не заменяет и не
  отменяет, так что снимать их обязана именно миграция. Свою службу и стену
  деинсталляция снимает сама: `uninstall` зовёт `core_filter::forget()` —
  постоянные фильтры переживают службу и без этого удалённый продукт оставил бы
  машину запертой.

  Служба в SCM: старую гасит и удаляет установщик (`LEGACY_SERVICE_NAME`, сторож
  — `the_installer_buries_the_old_service`). Остановка обязана идти до удаления:
  снятие правил висит на обработчике остановки. Удалить её, в отличие от своей,
  можно: `MARKED_FOR_DELETE` мешает зарегистрировать службу с тем же именем, а
  регистрируется другое.

  Каталог состояния: `settle()` переносит `privacy-gateway` в `proxybox` и
  только когда нового ещё нет, а не сумев перенести — работает там, где данные
  (сторож — `the_rename_never_loses_what_the_service_remembered`). Профили,
  подписки и список приложений лежат в одном `state.json`, и служба, начавшая с
  чистого каталога, выглядит как продукт, забывший всё.

  Автозапуск: `migrate_autostart` переносит запись `HKCU\...\Run` на новое имя
  и убирает старую. Именно переносит: тумблер человек включал сам. Старая запись
  указывает на exe прошлой установки, а он никуда не делся — установщик кладёт
  новый в каталог под новым именем, и после перезагрузки открывалось бы прошлое
  приложение с уже удалённой службой.
- Установщик гасит службу до копирования файлов
  (`NSIS_HOOK_PREINSTALL`): Tauri закрывает только своё окно, а `pg-service.exe`
  и `sing-box.exe` остаются занятыми — NSIS упирается в них на `File` и
  показывает «Error opening file for writing» вместо обновления. Гасим `net
  stop`, а не `sc stop`: второй возвращается на STOP_PENDING, когда файлы ещё
  заняты. Удалять службу на этом шаге нельзя — см. следующий пункт.
- Обновление не должно быть удалением. Страница Tauri «уже установлено» первым
  пунктом зовёт деинсталлятор старой версии без `/UPDATE`, и тот открепляет
  ярлыки, стирает автозапуск и удаляет службу. Установщик держит мьютекс
  (`PbHoldSetupMutex` через `MUI_CUSTOMFUNCTION_GUIINIT`), а `NSIS_HOOK_PREUNINSTALL`,
  найдя его, ставит `$UpdateMode 1` и службу только гасит. Своего шаблона
  `installer.nsi` нет намеренно — форк разъехался бы с Tauri. Сторож —
  `an_update_keeps_the_pinned_shortcuts`.
- `service::install` остаётся идемпотентной: установщик зовёт её при
  каждой установке, а служба к этому моменту уже может быть в SCM. Голый
  `create_service` отвечает ERROR_SERVICE_EXISTS — и обновление поверх выглядит
  как провал установки при полностью исправной службе.
- Тип узла из JSON или подписки сверяется с белым списком `core_config::NODES`,
  и это не вкусовщина: профиль `{"type":"direct"}` стартует, пробу проходит,
  служба снимает блокировку — и трафик идёт в открытую сеть под «Защищено».
  Чёрный список служебных outbound'ов этого не ловил: голый объект шёл мимо него.
- Подписка качается и по `http`, и это размен, а не недосмотр. По открытому
  каналу список узлов подменит любой, кто на пути, — не утечка, а подмена VPN
  целиком, — и `fetch()` долго отказывал всему, кроме `https`. Отказывал он своей
  же панели: 3x-ui отдаёт подписку с порта 2096 без TLS по умолчанию, и человек,
  поставивший её себе сам, вписывал `https://` и получал в ответ
  `SEC_E_INVALID_TOKEN` — код Windows, из которого не прочесть ничего. Вместо
  запрета — слово: `subscribe()` на нажатие (а не на плановую сверку, иначе
  строка приезжала бы раз в несколько часов как новое событие) кладёт строку в
  журнал, а заголовок группы в окне оставляет `http://` на виду, пряча только
  `https://`. Поднятый туннель закрывает открытый участок от провайдера, и
  сверка идёт через него. Сторож — `a_subscription_is_fetched_over_plain_http`.
- Журнал пишется на диск (`journal.json`) каждой строкой и переписывается
  целиком — тридцать строк, три килобайта. Значит, логировать в цикле нельзя:
  дедупликация повтора в `write_log` держит не только ленту, но и диск.
- Лента журнала в окне (`Journal.tsx`) читается post factum, поэтому сверху у
  неё «Все | Сбои» и «Скопировать». Отбор по сбоям идёт по признаку `bad` из
  службы, а не по словам в тексте (раскраска по словам объявила бы «правила не
  поставлены» неважным) и живёт только в окне: это способ смотреть, а не
  настройка. Когда сбоев в ленте не осталось, отбор не держится — пустая лента
  без кнопки, которая это объясняет, читалась бы как «журнала нет».
  Копируется то, что на экране. Сбойная строка занимает две строки и
  разворачивается нажатием (развёрнутое помнится по содержимому, а не по
  номеру: номера сдвигаются с каждой новой записью; нажатие, которым кончилось
  выделение текста, не сворачивает строку из-под руки). Подпись дня — липкая и
  живёт внутри группы своего дня, иначе липкому не к чему липнуть; отступа у
  прокрутки журнала нет по той же причине, что у профилей. Колонка времени
  одной ширины у всех строк. Сторож —
  `the_journal_filters_by_the_flag_from_the_service`.
- Метки браузерных профилей отбирают список той же полоской выбора
  (`Segmented`), что и везде в окне, а не своими плашками: меток бывает много, и
  полоска едет вбок (`w-max`), а не переносится вторым рядом. «Новый профиль» —
  акцентная кнопка с «+» и в шапке, и в пустом списке по центру: пустой список —
  единственное место, где она читается как первый шаг.
- Причину отказа туннеля в ленту пишет не проба, а сам sing-box. Наружу проба
  выносит только код SOCKS, и «не пропустил соединение (код 1)» одинаково
  выглядит и когда до сервера не доходит SYN, и когда сервер отказал в
  рукопожатии, и когда узел отвечает, но не пропускает: шесть обрывов за сутки
  читались как один и тот же неразличимый отказ. Настоящая строка есть, но
  лежит в `singbox.log`, и свести её с лентой можно было только сложив секунды
  аптайма из `ERROR[3129]` со временем запуска — руками.

  Тянет её `core_tunnel::last_failure`, и тянет **до** `svc.lock()`: файл
  местный, но это всё же диск, а под общим замком стоит окно, `supervise` и
  наблюдатель за смертью. Платим этим чтением только пока туннель лежит — на
  удачной пробе его нет вовсе. Ищется последняя строка с `outbound/`, и это не
  «любая ошибка»: тот же лог полон обрывов со стороны TUN (`raw-read tcp4
  172.27.234.1:… forcibly closed`) — там свою половину закрыло местное
  приложение, и к отказу туннеля это отношения не имеет. Взять последнюю
  строку без разбора значило бы заменить бесполезный код бесполезным шумом.
  Сторож — `the_reason_skips_the_noise_from_the_tun_side`. Читается хвост в
  16 КБ: файл живёт весь срок процесса и на болтливом узле растёт мегабайтами.

  До самого файла из окна пути не было вовсе — только «зайдите в
  `%ProgramData%`». Открывает каталог `open_logs` в оболочке, и путь у неё
  фиксированный: `open_url` рядом принимает ссылку и потому сверяет её с
  github.com, а принять путь от окна значило бы отдать ему открытие любого
  каталога машины. Рядом вторая дверь — `Request::SingboxLog`, тот же хвост в
  16 КБ строками (`core_tunnel::log_tail`, из него же берётся причина).
  Каталог открывает оболочка, то есть только Windows и только с Проводником, а
  хвост отдаёт служба — он есть везде, включая разработку в браузере.
  Разбирается запрос **до** `svc.lock()`, как иконка и обход диска: панель
  спрашивает его каждые две секунды, и под общим замком это чтение встало бы в
  одну очередь со статусом окна и надзором за туннелем. Сторож —
  `the_lock_is_never_held_through_a_walk_of_the_disk`.
- `Status::refreshed_at` двигает только удачная сверка, и по нему же считается
  срок следующей. Начнёте отмечать им попытку — плановая сверка перестанет
  случаться вовсе: недоступная панель будет откладывать сама себя.
- Уведомление в оболочке говорит о переходе `Up → Down`, а не о состоянии, и
  только при невидимом окне. Добавите сюда `Connecting → Down` — получите тост
  на каждый круг перезапуска, то есть раз в минуту при недоступном сервере.
- Адрес выдаёт FakeIP, а имя разрешает сервер. Запросы A и AAAA не уходят
  никуда: sing-box отдаёт адрес из `198.18.0.0/15` прямо из памяти, помнит, чьё
  это имя, и настоящее имя едет дальше вместе с самим соединением.

  До этого каждое имя стоило целого круга по каналу (`dns.final: remote` с
  `detour: proxy`, локального запасного пути нет намеренно) — и просадка канала
  убивала не байты, а имена, то есть страницу ещё до её начала. На живой машине
  это выглядело как «всё работает, кроме браузеров»: остальные к тому моменту
  сидят на разрешённых именах и тёплых соединениях, а браузер спрашивает новые
  непрерывно. Заодно стало строже с приватностью: резолвера, который видит имя
  до соединения, больше нет вовсе.

  Три вещи обязаны держаться вместе, и каждая проверена запуском 1.13.19 (A →
  `198.18.0.2` за 0 мс, AAAA → пустой NOERROR за 0 мс): AAAA отвечает пустым
  NOERROR отдельным правилом (`action: predefined`) — иначе он уходит на
  `remote`, то есть в туннель, и круг возвращается туда, откуда его убирали;
  у пула нет `inet6_range` — фальшивый AAAA увёл бы
  приложение в IPv6, которого наш TUN не держит; `independent_cache` — одно имя
  у `fake` и у `lan` имеет разные ответы. Локальные имена в правилах стоят
  **впереди** FakeIP, иначе `nas.lan` получил бы адрес из пула, то есть маршрут
  в туннель вместо роутера в соседней комнате. Адрес самого узла фальшивым не
  становится: его разрешает `default_domain_resolver`, а тот назван резолвером
  поимённо и `dns.rules` не проходит вовсе. Файла кэша (`store_fakeip`) нет и не
  будет: соответствие «фальшивый адрес — имя» это список всех посещённых сайтов,
  и класть его на диск значит завести тот самый журнал трафика, которого продукт
  не ведёт. Сторож — `fake_addresses_are_handed_out_locally`.
- Имена, которые всё-таки идут на сервер, держатся на трёх вещах сразу — убрать
  можно любую и получить ту же петлю.

  Первое: секция `dns` обязана быть. Без неё запрос уходил системному резолверу,
  попадал под маршрут по умолчанию и возвращался в тот же TUN — полтора ядра,
  девять десятых времени в ядре, полсотни «соединений» в секунду при пустом
  трафике.

  Второе: DNS машины обязан **перехватываться**
  (`{"inbound":["tun-in"],"port":[53],"action":"hijack-dns"}`). Секцию завели, а
  перехват — нет, и петля вернулась в другом виде: `sing-tun` под `auto_route`
  сам прописывает адаптеру DNS-сервером адрес шлюза (`Inet4Address[0].Next()`),
  Windows шлёт запросы туда, а ждать их некому — запрос становится обычным
  соединением, уходит в `final`, и на `direct` sing-box отбивает его мгновенно
  как петлю в свою же подсеть. Замер на живой машине: 1025 соединений из 1047 на
  `172.27.234.2:53`, сеть 0 Мбит/с, ЦП 85% (sing-box 45%, NisSrv 16% и гигабайт
  памяти под ней). Только на `tun-in`: вход `local` — путь пробы. Сторож —
  `the_machine_dns_is_hijacked_on_the_tun_only`.

  Третье: адрес самого сервера разрешается мимо туннеля
  (`default_domain_resolver: local`) — чтобы спросить `remote`, нужен уже
  поднятый `proxy`. Но `local` обязан быть назван **адресом и по DoH**, а не
  `type: local`: системный резолвер после `auto_route` — это адрес нашего же
  шлюза, то есть ссылка на себя, а с перехватом — замкнутый цикл. Стоит
  `https://8.8.8.8` — тот же резолвер, что у человека на адаптере, и
  шифрованный, потому что открытый UDP показал бы имя сервера сети по пути.
  `detour` у него нет и быть не должно: `detour: "direct"` на нашем пустом
  `direct`-outbound — это отказ старта («detour to an empty direct outbound
  makes no sense»), причём `sing-box check` его пропускает. Сторожа —
  `names_are_resolved_by_the_server_but_the_server_is_not` и
  `the_config_actually_starts`.
- Локальные имена разрешает роутер, а не сервер человека, и это следствие
  перехвата: без него DNS через туннель не работал вовсе, а с ним **всё** уходит
  на `remote` — включая `nas.lan` и голые односложные имена, которые раздаёт
  домашний роутер. Там они не разрешатся, зато уедут наружу. Резолвер берётся из
  аренды DHCP: адрес роутера в конфиге не назвать, он у каждого свой. Отказ DHCP
  не страшен (проверено на 1.13.19): sing-box пишет ошибку в журнал, стартует
  как обычно, а запрос возвращает NXDOMAIN за десятки миллисекунд — то есть
  худший исход равен поведению без правила, только имя наружу не ушло. Резолвер
  и правила заводятся всегда вместе и только при TUN: ссылка на несуществующий
  тег — отказ разбора, тег без ссылок — мусор. Сторож —
  `local_names_are_resolved_by_the_router`.
- Версия sing-box закреплена в `installer/get-singbox.ps1`, и снимать закрепление
  нельзя. Пока её выбирал `latest` с GitHub, версию в установщике выбирала дата
  сборки: 0.3.1 собрался через два дня после выхода 1.14.0, унёс его вместо
  1.13.x — и приватный режим не включался вообще, потому что 1.14 отвергает
  `strategy` в действии DNS-правила фатально. Код при этом не менялся ни
  строкой, и поймать это было нечем. Подъём версии — отдельная осознанная
  правка: замеров с пометкой «проверено на 1.13.x» тут десяток, и каждый новая
  версия вправе отменить. Ближайшее на очереди — `independent_cache`: в 1.14 он
  уже предупреждение, в 1.16 его удалят, а нам он нужен, пока мы на 1.13.

- Конфиг обязан не только разбираться, но и запускаться, и это разные проверки.
  `sing-box check` смотрит разбор; отказы вроде `detour` на пустой outbound
  вылезают только при `run`. Поэтому рядом с `*_passes_singbox_check` стоит
  `the_config_actually_starts` — он поднимает настоящий sing-box без TUN на
  свободных портах. Одного `check` мало: этим и пропустили конфиг, который не
  стартовал.

  Оба молча выходят, когда бинарника нет («проверять нечем»), и в CI его не
  было — то есть сторожа спали, а `cargo test` зеленел. Ровно так фатальный
  конфиг и уехал в 0.3.1. Поэтому оба workflow теперь кладут sing-box **до**
  тестов и передают его через `PG_SINGBOX`, а версию берут из
  `get-singbox.ps1`: закреплённая обязана быть одна на установщик и на CI,
  иначе CI зеленеет на версии, которой нет ни у кого.
- Сниффинг обязан висеть только на `tun-in`. Со `sniff` sing-box отвечает
  входящему раньше, чем дозвонится наружу: он ждёт первых байтов, чтобы прочитать
  имя. Проба же считает подтверждением ответ на свой SOCKS-запрос — накрой
  сниффинг вход `local`, и мёртвый узел станет подтверждённым туннелем, а
  `guard(false)` снимет блокировку. Сторож — `the_probe_path_is_never_sniffed`;
  первым это поймал `measure_fails_on_a_dead_node`.
- Ошибки TUN почти всегда означают не то, что написано: `explain()` переводит
  их в «нет прав администратора» или «рядом чужой туннель».
- Адрес TUN `172.27.234.1/30` и имя «proxybox» выбраны против умолчания
  sing-box (`172.19.0.1/30`), которое одинаково у NekoBox, Hiddify и v2rayN.
- Шлюз TUN (`172.27.234.2`) отбивается первым правилом маршрутизации, и это не
  украшение. Своим его никто не назначает — `sing-tun` выводит его как
  «следующий за нашим», — и отвечать по нему некому, а приложения исправно его
  опрашивают (SSDP на 1900, NAT-PMP на 5351, так ищут роутер). Без отбоя запрос
  уходит в маршрутизацию: на `direct` sing-box отбивал его сам и мгновенно, а
  приложение повторяло тут же — шторм, упирающий ядро в потолок при пустом
  трафике; на `proxy` тот же запрос стоит целого RTT, и повторов на три порядка
  меньше. Ровно эта разница и была разницей в расходе между охватами, которую
  долго списывали на объём трафика. `direct` из продукта ушёл, а правило отбоя
  осталось: платить целый RTT за опрос несуществующего роутера тоже незачем. Отбой обязан быть молчаливым (`method: drop`): обычный `reject`
  отвечает ICMP unreachable, то есть так же мгновенно, и шторм от него не
  прекращается — дешевеет лишь каждая итерация. И порт 53 обязан оставаться
  снаружи отбоя: под `auto_route` `sing-tun` прописывает адаптеру DNS-сервером
  этот же адрес (`Inet4Address[0].Next()`), так что безусловный отбой снёс бы
  разрешение имён всей машине — тише, чем шторм, и куда хуже. Кто именно
  обслуживает пришедший туда запрос, на живой Windows не проверено; пока не
  проверено — не трогаем. Константы связаны сторожем
  `the_gateway_is_next_to_our_address`, само правило — `the_tun_gateway_is_rejected_first`.
- Раскладка полей узла повторяет NekoBox; WireGuard в схеме sing-box 1.13 живёт
  в `endpoints`, не в `outbounds` — `build_config` различает по `type`.
- `tuic` в sing-box — это v5, и разбор ссылки берёт только его: v4 отдаёт один
  `token` вместо пары «UUID и пароль», и достроить из него узел нечем. Ссылка
  без одной из половин отвергается, а не достраивается пустой — профиль,
  который молча не соединяется, хуже пропущенной строки. Имена параметров
  читаются в обоих написаниях: через подчёркивание их пишут v2rayN и NekoBox,
  через дефис приезжает Clash-YAML, который мы сами же в ссылку и
  перекладываем.
- SOCKS5 и HTTP — узлы наравне с остальными (`socks`, `http` в `NODES`): так
  продаются резидентные и мобильные прокси, и без них браузерные профили не
  годились для основного сценария. Инвариант они не трогают — маршрута мимо
  узла нет, — но шифрования до сервера у них нет, и слово «Защищено» обязано
  оговориться: значком открытого замка в строке профиля (слово — в подсказке и
  для чтения с экрана; надпись «без шифрования» в каждой строке кричала громче
  имени узла) и в строке журнала при включении.
  Оговорку решает одна функция `core_config::plain`, и VLESS/trojan без TLS
  она называет так же (сторож — `a_plain_node_is_named_plain`). Строка без
  схемы (`host:port:user:pass`) — SOCKS5 (`a_bare_proxy_line_is_socks5`).
  Адрес `http://user:pass@host:port` вставка обязана считать узлом, а не
  подпиской: у прокси нет пути и запроса, а есть логин или явный порт
  (`core_config::is_proxy_url`, сторож —
  `a_proxy_address_is_not_a_subscription`). В окне то же правило стоит
  регуляркой `isProxyUrl` только ради подписи.

## Документация

README — витрина, а не справочник: обзор, инвариант, установка, быстрый старт,
принципы и оглавление. Всё длинное лежит в `docs/` по файлу на тему
(`how-it-works`, `install`, `profiles`, `browser-profiles`, `interface`,
`development`, `limitations`), и переводов у этих файлов нет: русский тут
исходный язык, и держать шесть копий справочника значило бы держать пять из них
устаревшими. Переведён только README — по файлу на язык, `README.<код>.md`, те
же шесть кодов, что у `Lang`. Строка переключателя стоит в шапке каждого из
шести файлов, и сторожа на неё нет: седьмой язык придётся дописать руками во все
шесть.

Сайт (`docs/index.html`) переключает те же шесть языков своим словарём внутри
страницы: страница статическая, GitHub Pages отдаёт её как есть, и собирать её
нечем. Словарь там один на страницу, а разметка одна на все языки — второй копии
HTML под перевод не заводится. Ключ здесь не русская фраза, а короткое имя
(`data-i18n`), потому что в разметке ключ стоит рядом с текстом по умолчанию, а
не вместо него.

Установщик тоже шестиязычный, и языки в нём в двух местах сразу:
`tauri.conf.json` перечисляет их для NSIS, а `installer/hooks.nsh` выбирает свою
строку по `$LANGUAGE` руками. `LangString` там не завести: Tauri включает
`hooks.nsh` раньше, чем грузит языки (`installer.nsi`, строка 34 против 470), а
внутри секции NSIS этой директивы не принимает вовсе. Тело макроса, наоборот,
разбирается в момент вставки — то есть уже внутри `Section Install`, где
`${LANG_*}` определены. Своих строк у Tauri нет для Farsi и Indonesian: они
лежат в `installer/languages/*.nsh` и подключены через `customLanguageFiles`.

## Стиль

Правило со словом «обязан» заводится вместе со сторожем, и абзац ссылается на
него по имени теста; без сторожа оно не соблюдается — проверено. Прозой живут
суждения и размены, а не правила.

Комментарии объясняют «почему», а не «что»; шапка модуля — рационал целиком.
Сознательное упрощение с известным потолком помечается комментарием
`ponytail:` с указанием потолка и пути апгрейда — их шестнадцать (два новых
завёл порт на Linux: номер `SO_PEERCRED` по архитектуре в
`crates/core-ipc/src/unix_socket.rs` и пропуск sing-box по uid вместо cgroup в
`crates/core-filter/src/linux.rs`), они настоящие, не выдумывайте новых и не
удаляйте молча. Снятый потолок снимается
вместе с комментарием и вместе со счётом в этой строке: срок сверки подписок
был двадцать первым и стал настройкой (`Settings::refresh_hours`), консольный
бинарник — двадцатым и стал службой SCM, возврат политики брандмауэра был
девятнадцатым и стал возвратом той политики, которую замок нашёл, буфер на
4096 процессов — восемнадцатым и стал растущим, сравнение версий строкой —
семнадцатым и стало numeric-коллатором, отсутствующее системное меню окна —
шестнадцатым и стало `TrackPopupMenu`, а ключ владельца порта без локального
адреса — пятнадцатым и стал `core_apps::Owner`. Четырнадцатым был замок правилами
`netsh` («тот же WFP, только без драйвера, подписи и unsafe-FFI»): он стал
пользовательским WFP без драйвера (`core-filter/src/wfp.rs`, единственный unsafe
крейта), и потолок «окно утечки по смерти процесса» с ним не исчез, а сузился —
в белом списке окна нет вовсе, остался только охват «весь компьютер». Он
записан заново в шапке `core-filter` и держит счёт на шестнадцати: один потолок
снят, один (меньший) заведён на его месте.

TS strict во фронтенде. Наружу не уходит ничего: ни телеметрии, ни логов
трафика; проба по умолчанию идёт на сервер самого пользователя.

`docs/limitations.md` («Чего ещё нет») — актуальный список известных дыр (в том числе:
три пункта фазы 0 и миграции переименования не проверены на живой Windows;
канал различает пользователя, но не программу). Держите его в курсе, когда закрываете пункт.
