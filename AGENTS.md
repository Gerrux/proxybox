# Правила работы с proxybox

Язык репозитория — русский: комментарии, доки, сообщения коммитов, строки
журнала и интерфейс. Пишите так же.

## Инвариант

Когда приватный режим включён, а туннель ещё не подтверждён, приложения под
защитой остаются без сети. Исключения и правила раздельного охвата задаёт
пользователь. Перед изменением маршрутизации или состояния службы сверяйтесь с
[инвариантом](docs/developer-reference.md#инвариант) и
[контрактом службы](docs/developer-reference.md#контракт-службы).

Проект не отправляет телеметрию и журналы трафика. Проба по умолчанию идёт
на сервер пользователя.

## Проверки

- `pnpm validate` запускает проверку TypeScript, сборку Vite и тесты Rust workspace.
- Для отдельного крейта используйте `cargo test -p <crate> <test_name>`.
  Тесты располагаются в `#[cfg(test)] mod tests` рядом с кодом.
- Tauri проверяется отдельно: `src-tauri` исключён из workspace. Команды,
  платформенные требования и переменные описаны в [разработке](docs/development.md)
  и [техническом справочнике](docs/developer-reference.md#команды).

## Стиль

- Правило со словом «обязан» добавляйте вместе с тестом. В документации
  указывайте имя теста, который проверяет это правило.
- Объясняйте причину решения в комментарии и мотивировку модуля в его шапке.
- Отмечайте сознательное упрощение через `ponytail:` с описанием ограничения
  и пути доработки. При добавлении или снятии ограничения обновляйте счётчик
  в разделе [«Стиль»](docs/developer-reference.md#стиль).
- Во фронтенде действует TypeScript strict. При закрытии известного ограничения
  обновляйте [список ограничений](docs/limitations.md).
- Пользовательские справочники ведите на русском в `docs/`. Переводите README
  для поддерживаемых языков и поддерживайте переключатели согласованными.
  Договорённости по сайту и установщику записаны в разделе
  [«Документация»](docs/developer-reference.md#документация).
