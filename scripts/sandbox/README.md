# Стенд proxybox в Windows Sandbox

Прогоняет службу (`pg-service.exe` + `sing-box.exe` + клиент `proxybox.exe`) в
одноразовой песочнице, чтобы стена брандмауэра (WFP) и замок проверялись на
настоящей Windows и не задевали живую службу на этой машине. Закрыли окно
песочницы — стенда нет.

## Что нужно

- Windows 10/11 Pro с включённым компонентом Windows Sandbox
  (`%SystemRoot%\System32\WindowsSandbox.exe` существует), виртуализация в BIOS.
- Rust (`cargo`) для сборки; доступ в интернет для скачивания sing-box (версия
  берётся из `installer/get-singbox.ps1` и кладётся в `target/sandbox/cache`)
  — либо `PG_SINGBOX=путь\к\sing-box.exe` на хосте.
- Windows Sandbox не может быть уже запущена.

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sandbox\run.ps1
```

Ключи: `-NoLaunch` (собрать витрину и `.wsb`, песочницу не открывать),
`-SkipBuild`, `-NoTun` (служба с `PG_TUN=0`: остаются проверки замка),
`-NoChecks` (только установка; проверки потом руками:
`powershell -ExecutionPolicy Bypass -File C:\pb-run\check.ps1`).

`run.ps1` собирает в `target/sandbox/stage` бинарники и скрипты, пишет
`target/sandbox/proxybox.wsb` (пути абсолютные; витрина смонтирована только
на чтение в `C:\pb`, `target/sandbox/out` — на запись в `C:\pb-out`).

Внутри `setup.ps1` копирует бинарники в `C:\pb-run`, поднимает второй sing-box
как SOCKS5-«узел» на адресе сетевой карты песочницы (порт 1080, выход direct),
собирает окружение (`PG_PROBE=1.1.1.1:443`, `PG_SINGBOX`, `PG_GEO=0`,
`PG_REFRESH=0`, `PG_LANG=ru`), ставит службу и записывает окружение её
собственным значением `Environment` (REG_MULTI_SZ) в
`HKLM\SYSTEM\CurrentControlSet\Services\proxybox`, перезапускает службу,
импортирует узел как профиль `node` и зовёт `check.ps1`. Переменные уровня
машины служба не видит до перезагрузки, они остаются только для клиента
(`PG_LANG`).

Журнал: `Desktop\proxybox-sandbox.log` внутри; копия на хосте —
`target/sandbox/out/proxybox-sandbox.log`.

## Что доказывает каждая проверка

| Проверка | Что доказывает |
|---|---|
| а1–а3 | Белый список: выбранный `curl.exe` выходит на `1.1.1.1`, его копия по другому пути и `powershell` — нет |
| б | Чужое разрешающее правило брандмауэра (`New-NetFirewallRule -Action Allow`) не открывает замок. На старой сборке (netsh) эта проверка **проваливается** — это и есть ошибка, которую чинит WFP |
| в1–в3 | Fail-closed: убит туннельный sing-box (по `singbox.pid`) — выбранный curl сразу без сети; служба сама поднимает туннель, доступ возвращается |
| г | Выбор `N` приложений подряд (`add-app` + `enable`): время каждой команды (ожидаются миллисекунды) и ноль отказов у фоновой петли curl по уже выбранному |
| д | Время от `on --profile node` до статуса Up (и до первого успешного curl) |
| е1–е3 | Режим выключен: всё работает, а `Get-NetFirewallProfile` (политика исходящего) не изменилась ни при включённом, ни при выключенном режиме |
| ж | Охват «весь компьютер»: невыбранная программа работает через туннель и закрыта, когда туннель убит |
| а4–а5 | Имена под замком: выбранный curl открывает `https://one.one.one.one` (щель `svchost` UDP/53), невыбранный — нет |
| а6 | `ipconfig /renew` под замком проходит (пропуск DHCP) |
| а7–а8 | Путь выбранного приложения с `/` получает пропуск; несуществующий путь не роняет стену, в журнале не больше одной строки «пропуск не выдан» |
| и1 | Замок закрыт на вход: в ядре есть наши фильтры на `ALE_AUTH_RECV_ACCEPT_V4` и `_V6` (разбор XML `netsh wfp show filters`) |
| и2 | **Ручная.** Невыбранный слушатель (`0.0.0.0:45678`) с разрешающим входящим правилом недоступен снаружи: с хоста `Test-NetConnection <адрес песочницы> -Port 45678` обязан дать `TcpTestSucceeded : False`. Из песочницы не проверить — соединение с собственным адресом идёт петлёй, а её стена пропускает. Адрес печатается в строке проверки |
| з1–з3 | Служба убита `Stop-Process` (автоперезапуск SCM отключён) — стена стоит (фильтры постоянные); `pg-service uninstall` её снимает, и в дампе `netsh wfp show filters` не остаётся фильтров провайдера proxybox. Разрушающая, идёт последней |

Цена входящего замка: под ним нет входящих RDP и SSH на машину (и в охвате
«весь компьютер», пока туннель не подтверждён), гости WSL2/Hyper-V тоже отбиваются.

Почти всё автоматическое; ручная только и2. Состав фильтров стенд сверяет
дампом `netsh wfp show filters` (проверки и1, з3).

## Что выяснил первый живой прогон (2026-10-04)

- TUN (wintun) внутри Sandbox поднимается, узел на адресе сетевой карты
  работает — `-NoTun` нужен только для проверки одного замка.
- Песочница из Store (Windows 11 24H2 и новее) команду входа из `.wsb` **не
  выполняет**: рабочий стол пустой, журнала нет. Поэтому `run.ps1`, найдя CLI
  `wsb`, поднимает среду через `wsb start` и запускает `setup.ps1` через
  `wsb exec -r System`. Окно просмотра для этого не нужно, и его обрыв
  («Подключение к песочнице потеряно», 0x80072746) среду не гасит —
  `wsb list` её видит. Остановить: `wsb stop --id <ид>`.
- Смонтированная витрина `C:\pb` — снимок на момент старта среды: файлы,
  положенные в `target/sandbox/stage` позже, внутри не видны. Живой канал
  в обе стороны — `C:\pb-out` (`target/sandbox/out`): разовые скрипты кладите
  туда и запускайте `wsb exec … -File C:\pb-out\<скрипт>.ps1`.
- VC++ runtime в чистом образе нет — `run.ps1` берёт `vcruntime140*.dll` с хоста.
- `cli` — встроенный псевдоним `Clear-Item`, и он сильнее функции; `check.ps1`
  снимает его до объявления своей `Cli`.
- **Трафик песочницы идёт через хост.** Если на хосте включён proxybox, узел
  песочницы выходит в сеть через туннель хоста (адрес выхода — узел хоста), и
  без всякой стены теряется примерно каждый пятый запрос. Поэтому проверки
  достижимости делают по три попытки, а отдельные «ПРОВАЛ» положительных
  проверок (а1, а4, а7, в3, ж) в одном прогоне при «ПРОЙДЕНО» в соседнем —
  это сеть хоста, а не стена. Чистые замеры — с выключенным приватным режимом
  на хосте.
- Имена в выводе клиента разобраны по `crates/pg-cli/src/main.rs` (русский
  язык, строка `туннель:`); поменяется формат — поправьте `Get-State` в
  `check.ps1`.

Скрипты лежат в UTF-8 с BOM (иначе Windows PowerShell 5.1 ломает кириллицу).
Правьте их редактором, который BOM сохраняет.
